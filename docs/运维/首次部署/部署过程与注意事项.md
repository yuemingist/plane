# 首次部署过程与注意事项（2026-11-13）

本文记录首次部署的完整过程、每个关键决策的原因和踩过的坑。改配置前先读第 4、5 节，
避免把「本地适配」误当成「上游 bug」修掉。

## 0. 结论速览

- 部署方式：官方本地开发流程。后端全家桶（DB/缓存/队列/对象存储/API/worker/beat/migrator）在
  Docker（`docker-compose-local.yml`），前端 4 个 app 在本机 tmux 里以 dev 模式跑。
- 没有改任何业务源码。所有本地化都落在：`.env` 文件、3 个 `vite.config.local.ts`（新增）、
  `.git/info/exclude`（本地 ignore）、`.logs/` 目录。

## 1. 网络环境：镜像拉取

**坑：`docker.io` 在当前网络不可达（公司 VPN 出口正常，GitHub 可达，唯独 docker.io 被墙 + DNS 污染）。**
表现为 `docker pull` 报 `TLS handshake timeout`，宿主机 curl `registry-1.docker.io` 也超时。

解决：临时启动 oixCloud（FlClash）代理，监听 `127.0.0.1:7890` 并设为系统代理；
OrbStack 自动跟随系统代理，拉取立即恢复。注意：

- 代理只在**拉镜像/装依赖**时需要，正在运行的服务不依赖它
- OrbStack 拉取的镜像、API 镜像构建（uv/PyPI/alpine 源）当时均可正常完成
- 若换回国内镜像源方案：改 OrbStack 的 Docker daemon `registry-mirrors` 配置即可，不要动系统代理设置

## 2. pnpm 版本

- 仓库 `package.json` 钉死 `packageManager: pnpm@11.10.0`（含 sha512）。
- 本机全局是 pnpm 12.15.0（Homebrew），**pnpm ≥10 默认开启按 `packageManager` 字段自动切换**，
  在仓库内执行即解析为 11.10.0，无需 corepack、无需 npx。
- `setup.sh` 里的 `corepack enable pnpm` 因 `/usr/local/bin` 无 root 写权限而失败（EACCES），
  这是 setup.sh 末尾报「Some issues occurred」的唯一原因，**可忽略**。
  若想装 corepack shim，自己执行 `sudo corepack enable pnpm`。
- 判断当前用的版本：仓库内 `pnpm --version` 应输出 11.10.0。

## 3. setup.sh 产物

- 生成 6 个 `.env`：根目录 + apps/{api,web,admin,space,live}
- `apps/api/.env` 末尾追加随机 `SECRET_KEY`（50 位）；根目录与 api 的
  `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` 替换为同一对随机值（MinIO 凭据，两侧必须一致）
- 敏感值不在本文档出现；丢了就重跑 setup.sh（会重置密钥与数据，需重跑迁移）

### S3 endpoint 决策（改代码前必读）

上传/下载走「API 颁发预签名 URL → 浏览器直传/直取 MinIO」模式（`plane/settings/storage.py`）：

- `USE_MINIO=1` 时预签名 URL 用**请求的 host**（即 API 的 :8000），本地开发没有反代把
  `/uploads` 转给 MinIO → 必 404。这是生产/proxy 模式专用，**本地开发不要开**。
- `USE_MINIO=0` 时预签名 URL 用 `AWS_S3_ENDPOINT_URL`，但这个地址同时被两类调用方使用：
  容器内的服务端操作（create_bucket、worker 上传）和浏览器。前者够得着容器网络名
  `plane-minio:9000`，后者只够得着 Tailscale/localhost —— 一个变量无法两全。
- **解法**：`http://yuemingmac-mini.tail43aa97.ts.net:9000` 两侧都可达
  （容器经宿主 DNS/路由解析 Tailscale 名，浏览器经 Tailscale 直连）。
  已验证：API 启动日志 `Bucket 'uploads' exists.`（容器内 create_bucket 成功）。
- 已知副作用：在本机用 `localhost:3000` 浏览时，上传仍会指向 Tailscale 主机名（本机也能解析，可用）。

## 5. 前端启动：为什么不用根目录 `pnpm dev`

`apps/{web,admin,space}/vite.config.ts`（业务源码）写死 `server.host: "127.0.0.1"`，且 Vite dev
server 的 `allowedHosts` 白名单不含自定义域名。直接跑会出现：

- 只监听 127.0.0.1 → 远程设备连不上
- 用 Tailscale 主机名访问 → `403 Blocked request. This host (...) is not allowed`

CLI 参数能覆盖 host（`react-router dev --host 0.0.0.0`），但 **allowedHosts 没有 CLI 参数**。
react-router CLI 支持 `-c/--config`，于是：

1. 新增 3 个本地包装配置 `apps/{web,admin,space}/vite.config.local.ts`：
   import 原配置 → `mergeConfig` 合并 `server.host: "0.0.0.0"` +
   `server.allowedHosts: ["yuemingmac-mini.tail43aa97.ts.net"]`
2. 启动命令用 `-c vite.config.local.ts`（见 README）
3. 3 个文件已加入 `.git/info/exclude`（本地 ignore，不污染 fork 的 git status；
   若想提交请先从 exclude 移除）

其余坑：

- **pnpm 传参**：`pnpm dev -- --host 0.0.0.0` 里的 `--` 会被原样透传给脚本，导致
  react-router 报 `React Router Vite plugin not found in Vite config`。用
  `pnpm exec react-router dev ...` 显式命令最稳。
- **turbo 并发**：`turbo run dev` 默认并发 10，仓库有 11 个持久 watch 任务，会报
  `Invalid task configuration`，必须带 `--concurrency=18`（根 package.json 的 dev 脚本就是这么写的）。
- **包依赖**：app 的 dev 不经过 turbo 时需要 `@plane/*` 包的 dist 已构建。
  先起 `pkg` 窗口（turbo 的 dev 任务自带 `dependsOn: ^build`，会先构建再 watch），再起各 app。
- live 服务（Express/Hocuspocus）`listen(port)` 默认绑全部接口，无需处理；
  HTTP 路由挂在 `/live` 下（健康检查 `/live/health`）。

## 7. 遗留问题与注意事项

1. **代理依赖**：以后 `docker pull` 新镜像、`pnpm install` 装新依赖时需开 oixCloud；运行中的服务不需要
2. **corepack**：未启用（无 root）；pnpm 自动切换已覆盖
3. **上传大小**：默认 5MB（`FILE_SIZE_LIMIT`，api/.env）
4. **改主机名/IP**：要同步改 4 个 .env + 3 个 vite.config.local.ts + `CORS_ALLOWED_ORIGINS`，改完前端要重启
5. **后端代码改动**：api 容器是源码 bind-mount + runserver（`--settings=plane.settings.local`），
   Django 会自动重载；worker/beat 同理，但 Celery 进程改代码后建议 `docker compose restart worker beat-worker`
6. **数据重置**：`docker compose down -v` 会删掉全部数据卷（库、上传文件），除非确定重来否则禁止
7. **内存**：全套约 3.2GB（Docker 1.4G + 前端 1.8G），16GB 机器余量充足；若再跑重活注意 worker 是大头（776MB）

## 8. 故障排查速查

| 症状                                             | 大概率原因                            | 处理                                                               |
| ------------------------------------------------ | ------------------------------------- | ------------------------------------------------------------------ |
| 远程访问 403 `Blocked request. This host ...`    | 没用 `-c vite.config.local.ts` 启动   | 用 README 里的启动命令                                             |
| 远程连不上但本机 localhost 正常                  | dev server 绑了 127.0.0.1（同上原因） | 同上；`lsof -nP -iTCP -sTCP:LISTEN` 确认应在 `*`                   |
| `docker pull` TLS handshake timeout              | docker.io 被墙且代理没开              | 开 oixCloud（系统代理 7890），OrbStack 自动跟随                    |
| API 500 / 上传失败                               | MinIO 凭据或 endpoint 不对            | 看 `docker compose logs api`；核对两侧 .env 的 AWS 三件套一致      |
| 前端起不动：`React Router Vite plugin not found` | pnpm 透传了 `--` 或没装依赖           | 用 `pnpm exec react-router dev` 命令；确认 `pnpm install` 跑过     |
| turbo 报 `Invalid task configuration`            | 没带 `--concurrency=18`               | 补上参数                                                           |
| 页面能开但数据加载失败                           | API 没起 / CORS                       | `curl :8000`；核对 `CORS_ALLOWED_ORIGINS` 含当前页面来源           |
| 实时协作（多人编辑）不通                         | live 没起或 Redis 断                  | `curl :3100/live/health` 应 200；`docker compose logs plane-redis` |
