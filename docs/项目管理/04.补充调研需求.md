# Plane 里程碑① 补充调研需求

> 输入：mini `~/Develop/plane/docs/` 下 zcode 团队的全部调研产出（01/10/11/12 号主文档、16 个模块 `对比.md` + 177 张截图 + 27 份 HTML 快照、`20.整体UI对比总文档.md`、项目管理 4 份文档）。
> 评估日期：2026-11-14（Plane助理阅读后评估；读过 01/10/11/12/20 全文或关键章节、20/54/23/51/52/31 等模块对比，以及项目管理文档）。
> 用途：①给明哥一个「现有调研够不够开工」的明确结论；②明确缺什么、怎么补、怎么验收；③配套可直接执行的 [zcode调研提示词.md](zcode调研提示词.md)。

## 0. 结论（一句话版）

**不充分。** 现有调研是一份质量不错的「全貌地图 + 方向判断 + P0 点亮候选清单」，足以回答「差在哪、先点哪几盏灯」；但**还不足以支撑里程碑①「追平商业版功能与 UI」的开工与排期**。主要缺口：

1. 功能清单只到「有没有」的粒度，没有到「版本/套餐边界已实测验证 + 每项功能的行为规格」；多个商业功能（时间跟踪/工作日志、客户、发布、项目更新、模板、里程碑、计划、团队空间、Wiki、工作流、自定义属性、重复工作项、自定义自动化构建器……）只停在「设置侧边栏有一行」或「页面空态」，**没有进到功能里面**。
2. UI 对比以「页面级截图 + 差异一句话」为主，**不是可照着做的交互规格**（缺关键状态、完整操作流、字段与校验、视觉 token、满数据态）。
3. 代码侧只有「模块级盘点 + P0 的若干文件路径」，**没有逐功能的改造切入点清单**（后端 model/URL/view/serializer/迁移，前端 store/service/组件/i18n，测试，上游冲突面）；承诺过的 git 历史考古（被摘除功能的旧实现）**没有执行**。
4. 商业版数据模型/API 只有「v2 有 407 个 op」的概览，**没有落成每个功能域的实体-字段-端点草案**。
5. AGPL 只有要点级说明；没有逐文件/依赖/商标/商业条款的边界审计，不足以支撑「大量复刻商业功能」的合规决策。**（明哥 2026-11-14 决定：R8 暂缓，对外商业化前再做；当前仍沿用「不获取 plane-ee、不抓取云端内部 API、不复制云端前端代码」红线。）**
6. 官方 release/roadmap 只有一个时间点快照（`v1.5.0-rc2`、changelog 首页）；**没有时间线与持续跟踪机制**，而追赶对象是移动靶（云端里程碑功能自己还在迭代）。
7. 优先级只有「点亮难度」一个维度（P0/P1/P2），**没有价值/依赖/冲突风险/合规/与 M2 重叠**的评分，也没有「追平到什么程度算完成」的验收标准。
8. 文档之间存在**未回写的修正**：20 号总文档记录了 15 条「实测修正」，但 01/10/11 原文仍保留旧结论，读者容易读到过期判断。

**时间紧迫点**：云端 Business 试用（YM Research 工作区，slug=thinkym）**2026-11-28 到期**（距今 14 天），到期后自动降为 Free；所有需要在云端 Business 态实测的补充（见 R3/R4）必须在此前完成，**应最先做**。

### 1.2 做得好的地方（后续补充应保持）

- 双线核实（官方资料 × 代码）并给出可信度分级；明确区分「代码没有」与「代码有但关闭」；
- 发现并验证了一批「点亮已有代码」的高性价比项（批量操作、Epics/Types、Space、Active Cycles、依赖箭头）；
- 套餐墙实证（同日同部署的 Free vs Business 对比）、CE 反超项清单；
- 合规红线清晰：不获取闭源 `plane-ee`，只用 MIT 的 SDK/MCP/helm 公开材料；
- 每个模块一个目录、`对比.md` + 截图 + HTML，结构统一，可复用此框架继续补。

### 1.3 已知的先天局限（调研文档自己也承认）

- CE 实例是空造数环境（27 条工作项，通知/评论/多人协同基本为空）；
- 云端只有 Business 试用，**Pro 档与 Enterprise 档边界未实测**，仅靠 pricing 页；
- 多处截图缺失（54 模块 5 张、55 模块 8 张等），以 DOM 文本替代；
- 自定义自动化构建器、Slack OAuth 之后流程、Jira 导入后续步骤等「点进去才看得到」的部分未展开；
- U13（官方移动 App 连自托管 CE）未实测；多用户实时协同未实测；云端通知内容形态未覆盖。

## 3. 补充调研项

> 编号 R1–R12。每项：目的 → 范围 → 方法 → 交付物（路径均相对 mini `~/Develop/plane/docs/01.追赶正式版/`）→ 验收标准 → 约束。

### R1　正式版功能基线：套餐/版本级 + Feature Flag 对照（统一功能编号 F-ID）

- **目的**：建立一份「官方说法 × 实测 × 代码」三列对齐的功能基线，成为 M1 唯一的功能总清单，替代 D/U/P 多套编号。
- **范围**：
  1. 套餐维度：Free / Pro / Business / Enterprise Grid / 自托管 CE / Commercial Edition / Airgapped 每项功能的归属（来源：pricing 页、docs 的 billing/plans、changelog、`packages/constants/src/subscription.ts` 文案）。
  2. 官方 feature flag 全集（12 号第 4 节 E 与 SDK `features` 模型）：customers / initiatives / releases / wiki / teamspaces / PI / work-item-types / workitem-hierarchy / state-duration / project-grouping / automated-cycle / parallel-cycle / milestone / epic / workflow / update 等，逐项映射到 UI 入口与前端设置位置。
  3. 把 20 号总文档未覆盖的功能补进来：时间跟踪/工作日志、项目更新(Updates)、Memory、SLA、Databases、状态时长、项目分组、工作项层级、增强搜索、导出（队列/高级）、Estimates 高级、周期自动转移/并行周期、访客/角色边界、Home/便签/草稿等。
- **方法**：读 10/12/20 号 + 官方资料（docs.plane.so、plane.so/pricing、changelog、SDK features 模型）；对每条功能给出 F-ID；对已有 D/U/P/D-xx 编号建立映射列；**能在云端 Business 试用验证的就实测验证（与 R3 联动）**。
- **交付物**：`01.功能调研/13.正式版功能基线.md`（主表）+ `13.正式版功能基线.csv`（同表，便于后续进 Linear）。
  - 主表列：F-ID｜功能域｜功能名｜官方套餐归属（Free/Pro/Business/EG）｜自托管归属｜Feature Flag 键｜云端 UI 入口路径｜云端实测状态（已实测/仅官方资料/未触达）｜CE 现状（无/壳/部分/有）｜旧编号映射（D/U/P/D-xx）｜证据链接｜复核日期。
- **验收标准**：
  - 覆盖 20 号路线图 40 条 + 01 号 50 条 + 本文 1.3 列出的未覆盖功能，**无遗漏条目**（交付时附「覆盖校验表」：旧编号→F-ID 逐一可查）；
  - 每条的「套餐归属」必须有出处链接；与 pricing 页冲突处标红并说明；
  - 云端实测状态为「未触达」的条目 ≤ 10%，且每条写明原因；
  - 至少 30 个 F-ID 有 Feature Flag 键或明确标注「无 flag」。
- **优先级/难度**：P0（所有后续项的索引）／M。

### R2　官方文档与 API 文档逐功能抽取（行为规格 + 术语）

- **目的**：把官方公开文档（产品行为说明）变成可对照的规格，补齐 UI 截图看不到的规则（权限、边界、限制、默认值、状态机）。
- **范围**：docs.plane.so 全部功能页（work items、cycles、modules、views、pages、intake、analytics/dashboards、AI、integrations、importers、automations、workflows、time tracking、customers、releases、templates、teamspaces、initiatives、wiki、roles & permissions、billing…）；developers.plane.so（自托管、API reference、webhook、MCP）。
- **方法**：按功能域逐页读取并**摘要**（只写摘要+链接，不整页复制）；提取：功能定义、入口、权限矩阵、限制/配额、默认值、术语（中英对照，用于 i18n）、已知限制/FAQ。
- **交付物**：`01.功能调研/14.官方文档逐功能摘要/<功能域>.md`（每域一个文件，统一模板：定义｜入口｜规则与限制｜权限｜术语表｜出处链接｜与 F-ID 对应）+ `14.官方文档逐功能摘要/00.术语表.md`。
- **验收标准**：覆盖 R1 中全部商业/付费 F-ID 的对应官方文档页（无文档的写明「官方无文档」）；每个摘要含出处链接与抓取日期；术语表 ≥ 150 条中英对照；无整段照搬原文。
- **优先级/难度**：P1／M。

### R3　云端 Business 实测深测补完（含 11-28 到期前必做）

### R4　交互与视觉规范层（设计 token + 状态矩阵 + 键盘流）
