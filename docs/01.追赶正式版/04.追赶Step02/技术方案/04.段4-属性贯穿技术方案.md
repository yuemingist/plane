## 1. 列表响应属性值聚合（避免 N+1）

- 落点：`IssueViewSet.list`（`apps/api/plane/app/views/issue/base.py:269`）与 `IssueListEndpoint.get`（:87）。〔已确认〕两处最终产出行 dict。
- 实现〔设计决策〕：不 annotate/subquery（JSONB 聚合子查询成本高），改**分页后批量补值**——新 util `apps/api/plane/utils/property_values.py`：
  - `attach_issue_property_values(rows, project_id)`：对页内 rows（≤100 行）做 1 次查询 `IssuePropertyValue.filter(issue_id__in=页内ids, issue_property__project_id, issue_property__is_active=True, deleted_at__isnull=True)`，`values_list("issue_id","issue_property_id","value")` 分组后逐行写 `row["issue_property_values"] = {property_id: value}`；无值行写 `{}`。**每页恒定 +1 查询**，无 N+1（pytest `assertNumQueries` 断言）。
  - 出参形态：`issue.issue_property_values: Record<propertyId, rawJSON>`；前端按行 `type_id` 的绑定属性映射渲染，双门控语义由查询条件承担（池级 is_active）+ 绑定由前端 store 判定。

- 绑定取数（前端）：新 hook `apps/web/hooks/use-project-issue-properties.ts`——拉项目属性池 + 逐类型绑定（类型数小，一次缓存），仅当 `project.is_issue_type_enabled`。

## 3. 筛选扩展（rich filters 体系内最小实现）

- 前端键：`customproperty_<属性id>`。〔已确认〕上游已铺路：`shared-state/adapter.ts` `_isValidWorkItemFilterConditionKey` 白名单已放行 `customproperty_` 前缀；`packages/utils` 预置 `TCustomPropertyFilterParams` / `getMemberPickerPropertyFilterConfig` / `getDatePropertyFilterConfig` 工厂。类型面：`TWorkItemFilterProperty` 并 `| (string & {})`、`TWorkItemFilterConditionData` 加 `customproperty_` 模板索引签名。
- 控件分派（产品方案 §3 裁剪）：新增工厂 `getCustomPropertyFilterConfig`（packages/utils/work-item-filters/configs/filters/custom-property.ts）——option→`getMultiSelectConfig`（`__in`）、member→复用 member-picker（`__exact`）、date→date 工厂（`__exact`，range 不做）、boolean→`getSingleSelectConfig` 是/否（`__exact`）；text/decimal/url/rich_text 不出 config（rich filters 无文本输入控件）。
- 配置挂载：`useWorkItemFiltersConfig`（apps/web/hooks/work-item-filters/use-work-item-filters-config.tsx）按 projectId 读取属性池（经 §1 hook），逐启用属性追加 config（isEnabled 恒 true，属性消失时 config 随 store 消失）。
- 后端：
  1. `IssueComplexFilterBackend(ComplexFilterBackend)`（utils/filters/filter*backend.py 新类）——覆盖 `_validate_fields`（放行 `customproperty*\*`，其余仍走父类白名单）与 `_preprocess_leaf_conditions`（把 `customproperty_<id>**<op>` 重写为合成键：exact→`custom_property_values` 列表、in→`custom_property_values**in`列表，值编码`<属性id>:<原值>`；属性 id 无冒号、文本值经 `split(":",1)` 保留）。**只挂到 IssueViewSet/IssueListEndpoint**，其余端点沿用原 backend 零回归。
  2. `IssueFilterSet` 声明两个 method 过滤器 `custom_property_values` / `custom_property_values__in`（method 返回 Q）：按属性 id 取属性定义（不存在/跨项目→`Q(pk__in=[])` 空匹配），按 property_type 做值类型规整（boolean→bool、decimal→float、其余字符串），单值 `Q(issue_property_values__value=<v>)`；多选容器（option/member is_multi）用 `value__contains=[v]`（JSONB @>），组内 OR、组间 AND（与 rich filters 语义一致）。

- 值编码走 `filters` JSON 参数，与既有 rich filters 链路同管道〔已确认 issue-filter-helper.store.ts:118〕。
