## 1. 后端

### 1.1 模型（新文件 `apps/api/plane/db/models/workflow.py`）

| 表                  | 字段                                                                                                                                                                                                                  | 说明                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Workflow`          | 继承 `ProjectBaseModel`（project/workspace FK + id/created_by/updated_by/created_at/updated_at/deleted_at）；`name` CharField(255, default="Default Workflow")；`is_active` BooleanField(default=True)                | 项目至多一条非删除行：partial UniqueConstraint `(project) WHERE deleted_at IS NULL`（Business=单一 Default Workflow）；`db_table="workflows"` |
| `WorkflowChangeLog` | 继承 `BaseModel`；`workflow` FK→Workflow（related_name="change_logs", CASCADE）；`actor` FK→User（SET_NULL, null=True）；`action` CharField(choices: `enabled`/`disabled`/`re_enabled`)；`note` TextField(blank=True) | 生命周期留痕；`db_table="workflow_change_logs"`；时间戳用 `created_at`                                                                        |

- 禁用不删行：`is_active=False`，再启用复用同一行（产品方案 §3 状态机）。
- 两模型注册进 `plane/db/models/__init__.py`（追加 import，不动既有行）。

### 1.3 端点（新文件 `app/serializers/workflow.py`、`app/views/workflow.py`、`app/urls/workflow.py`）

项目域扁平路由（kebab-case 路径，同 `work-item-types/` 形态）：

| 方法+路径                                             | 动作       | 权限                                    | 行为                                                                                                                                             |
| ----------------------------------------------------- | ---------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/workspaces/{slug}/projects/{id}/workflows/` | 列表       | allow_permission [ADMIN, MEMBER, GUEST] | 未启用 → 200 `[]`（门卡语义：可读空态，产品方案 W-1）；启用 → 恰 1 行（name/is_active/created_at 等透出）                                        |
| `POST …/workflows/enable/`                            | 项目级启用 | [ADMIN, MEMBER]                         | 事务：已有活动行 → 400；有禁用行 → `is_active=True`（再启用）+ 历史 `re_enabled`；无行 → 建 `Default Workflow`（is_active=True）+ 历史 `enabled` |
| `GET …/workflows/{workflowId}/`                       | 详情       | 读三角色                                | 跨项目 id → 404                                                                                                                                  |
| `POST …/workflows/{workflowId}/disable/`              | 停用       | [ADMIN, MEMBER]                         | `is_active=False` + 历史 `disabled`；已禁用 → 400                                                                                                |
| `POST …/workflows/{workflowId}/enable/`               | 单行再启用 | [ADMIN, MEMBER]                         | `is_active=True` + 历史 `re_enabled`；已活动 → 400（API 对称保留；UI 走项目级 enable）                                                           |
| `GET …/workflows/{workflowId}/change-history/`        | 历史分页   | 读三角色                                | 按 `-created_at` 分页；含 actor 展开字段（id/display_name/avatar）+ action + created_at + note                                                   |

- 权限域绑定（Step01 §2.3 模式）：queryset 一律 `workspace__slug + pk=project_id + project_projectmember__member=request.user, is_active=True` 过滤。
- 门卡语义与 Step01 的差异（有据）：工作流未启用**不 403**——前端门卡页需要一次只读请求判断空态（产品方案 W-1）；写操作照常被角色权限拦截。
- 历史写入与状态变更同一事务；actor 取 `request.user`（BaseModel 自动 created_by 兜底，但 disable/enable 不新建 log 行而是显式 `WorkflowChangeLog.objects.create(actor=request.user, …)`，避免依赖 crum 中间件的隐式行为）。

### 1.4 序列化器

- `WorkflowSerializer`：`id, name, is_active, project, workspace, created_at, updated_at`（只读为主，name 不可改——本段无改名入口）。
- `WorkflowChangeLogSerializer`：`id, action, note, created_at, actor` + `actor_detail`（SerializerMethodField：display_name/avatar/first_name）。
