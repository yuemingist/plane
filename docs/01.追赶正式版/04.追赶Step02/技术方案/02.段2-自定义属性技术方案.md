## 1. 模型设计（3 新表，CE 从零建）

CE 无任何属性 schema（18-01 §4：旧 `IssueProperty` 0071/0114 迁移改名链为用户显示偏好 `ProjectUserProperty`，与本域无关）〔已确认〕。新表全部挂在既有 `db` app，新文件 `apps/api/plane/db/models/issue_property.py`：

### 1.1 IssueProperty（项目属性池）

| 字段              | 类型                                                | 说明                                                            |
| ----------------- | --------------------------------------------------- | --------------------------------------------------------------- |
| workspace/project | ProjectBaseModel 继承（含 workspace FK）            | 项目级池                                                        |
| name              | varchar(255)                                        | 显示名（弹窗「标题」）                                          |
| description       | text blank                                          | 描述                                                            |
| property_type     | CharField(max_length=30, choices=IssuePropertyType) | 8 类枚举：text/decimal/option/boolean/date/member/rich_text/url |
| settings          | JSONField(default=dict)                             | 子配置（产品方案 §2 逐类结构）                                  |
| is_required       | bool default False                                  | 「必填属性」                                                    |
| is_active         | bool default False                                  | 双门控：创建默认禁用                                            |
| default_value     | JSONField(null=True)                                | 数字默认值/下拉选项 id/成员 id 等                               |
| sort_order        | float default 65535                                 | 排序                                                            |
| 约束              | UniqueConstraint(project, name, deleted_at isnull)  | 项目池内重名 400                                                |

### 1.2 IssueTypeIssueProperty（绑定桥）

issue_type FK→db.IssueType（related_name=`issue_type_properties`）、issue_property FK→IssueProperty（related_name=`issue_type_bindings`）；unique(issue_type, issue_property, deleted_at isnull)。无独立 is_active——启用门控由属性池 `is_active` 承担（57 号「启用将在所有已关联的工作项类型中生效」语义〔实测〕，产品方案 §4）。

### 1.3 IssuePropertyValue（属性值）

issue FK→db.Issue、issue_property FK→IssueProperty；`value = JSONField(null=True)`（按类型存 string/number/bool/ISO 日期/选项 id 数组/成员 id 数组/html）；unique(issue, issue_property, deleted_at isnull)。actor 语义由 BaseModel 的 created_by/updated_by 承担（谁最后写入）。值类型校验在 serializer 层按 property_type 分派（§2.3），DB 层不做 typed 列（is_multi 数组语义与官方 partial unique 并轨预案见 §5）。

选项集：`settings.options = [{"id": uuid, "name": str, "is_default": bool}]`（产品方案 A1）。值引用选项 id，改名不影响存量值。

### 2.1 权限（对齐 Step01 §2.3）

`allow_permission([ROLE.ADMIN, ROLE.MEMBER, ROLE.GUEST])` 读；`[ROLE.ADMIN, ROLE.MEMBER]` 写。queryset 一律 `workspace__slug + project_id + project_projectmember__member=request.user, is_active=True` 成员域过滤〔已确认 Step01 模式〕。

### 2.2 池 CRUD 校验（8 类）

| 校验                    | 规则                                                                                                         | 失败                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| property_type 枚举      | 8 类白名单                                                                                                   | 400                           |
| 下拉选项集              | `settings.options` ≥1 项且 name 非空；选项 id 服务端生成                                                     | 400（产品方案 §4）            |
| 下拉/成员 default_value | 必须属于选项集/项目成员                                                                                      | 400                           |
| 数字 default_value      | 数值型；decimal_places 0-8 整数；format ∈ standard/percent/currency                                          | 400                           |
| URL                     | 保存时不校验定义，**值写入时**校验（§2.3）                                                                   | —                             |
| 重名                    | 项目池内同名（未删除行）                                                                                     | 400                           |
| 类型切换                | 编辑弹窗允许改 property_type 吗？**不允许**（PATCH 忽略 property_type 变更；有值或绑定后改类型会破坏值语义） | 忽略 + 文档串注明〔设计决策〕 |

### 2.3 值写入校验（按 property_type 分派）

1. 属性必须：属于 URL 项目池 + 绑定到该 issue 的 type + `is_active=True`（双门控在服务端兜底）〔设计决策〕。
2. 分派校验：text→str（readonly 仍可写，UI 层禁用）；decimal→int/float；option→选项 id（单值 str / 多值 list，均须 ∈ options）；boolean→bool；date→ISO 日期串（dateutil 解析失败 400）；member→项目成员 id（单/多）；rich_text→str；url→`validators.URLRenderer` 风格正则/`urllib.parse` 校验 400。
3. 空值（null/""/[]）→ 删除该值行（清空语义）。
4. 批量写入单事务；任一属性校验失败整体 400。
