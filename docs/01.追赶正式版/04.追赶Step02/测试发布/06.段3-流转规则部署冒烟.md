## 2. 缺陷清单（本轮新发现）

| #9  | **P3（文案瑕疵）**                 | 拒绝路径出现**第二条**错误 toast 泄漏原始 i18n ICU 占位符：**「错误！{count, plural, one {工作项} other {工作项}}更新失败」**（应为「工作项更新失败」一类的正确翻译）。与正确的拒绝 toast（「无法移动工作项受工作流规则限制，不允许从「X」移动到「Y」。」）同时弹出，两条并存      | 详情页/拖卡把工作项改到规则不允许的状态 | 拒绝提示功能本体正常（专用 toast+回滚+400 均正确），但通用错误 toast 的 i18n key 使用了复数 ICU 语法而当前 i18next 配置（`nsSeparator:false`+`keySeparator:"."`）不做 ICU 插值，原样回显。建议该错误提示改用普通键值或补 ICU 处理 |

## 3. API 复核记录（session 认证，mini api:8000）

- `PATCH …/issues/<WEB-23>/`（state=Done，规则 Todo→In Progress 生效期）→ **400**，body：`{"error":"This state transition is not allowed by the project workflow.","code":"workflow_transition_not_allowed","from_state_name":"Todo","to_state_name":"Done"}`。

**段 3 部署冒烟：通过（1 个新记录 P3 缺陷）**。7 项冒烟全部命中：规则矩阵 UI 可展开可配置可保存（形态=方案 §2.1 chip 矩阵）；保存 toast 逐字命中；规则变更历史留痕实测；正向流转 204+活动留痕；非法迁移 UI 与 API 双路径 400+状态回滚+专用拒绝 toast；无规则源状态不受限（GWT-4）；清空规则恢复全部允许；#7/#8 两项段 2 遗留修复在 mini 部署版复验通过；回归零异常。

**假设清单口径更新（05 号 §5 的「仍属假设」项）**：

- **A5（ADMIN 也受约束）：已实测确认**——管理员账号在 UI 与 API 双路径均被 400 拒绝。
- **A2（默认无规则全允许 / 白名单按源状态）：已实测确认**——配置前 17 条工作项行为无变化；仅 Todo、QA Testing 受限，其余源状态自由；清空即恢复。附带实证「全禁」不可表达（空选=不受限），与 A2 语义自洽。
- **A3（规则变更写更改历史）：已实测确认**——「更新了流转规则」事件在历史面板置顶。
- **A7（界面文案 CE 自拟）：保存 toast 逐字命中；拒绝 toast 实际文案与方案示例语序不同但语义一致（自拟范围内）；另发现通用错误 toast 的 ICU 占位符泄漏（新缺陷 #9）**。
- A1（粒度不含成员/条件）、A4（只约束 PATCH）、A6（软删除状态陈旧行）属后端语义，pytest 19 条已覆盖，本轮未重复 UI 面。

**遗留事项**：#9（P3，ICU 占位符泄漏 toast）建议随后续段顺手修（一处 i18n 键改普通键值即可）。无 P2 遗留，段 3 可收尾。
