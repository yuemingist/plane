## 1. 目标与非目标

**目标**：CE 项目设置出现「工作流」页（工作结构分组，位于「状态」与「标签」之间，对照截图 1 侧栏顺序：工作项类型/状态/工作流/标签/估算）。未启用 → 门卡开关；启用后 → Default Workflow 行（覆盖项目状态）；可查看更改历史；可禁用/再启用。

**不做（本段明确排除）**：

- 审批流（Enterprise，58 号 D-11：Business 不可见不可配）。
- 「多套工作流」管理界面/新建工作流入口（Business 仅单一 Default Workflow，58 §1.3 边界行）。
- 状态流转规则、每状态「允许新建」开关、流转成员名单（58 §3.6 步骤 6：状态页行菜单无这些项，Enterprise 档）。
- 行内规则编辑/详情页：云端点行主体无响应（58 §3.6 步骤 3），本段同样不做行点击跳转。

### 2.5 更改历史（截图 4）

- 形态：右侧滑出面板，标题「变更历史」（**逐字**，复用既有 `common.change_history`=「变更历史」；截图 4），右上排序图标 + 关闭 X。
- 云端 Business 实测为空面板（58 §3.6 步骤 5：「Default Workflow 无自定义变更」——规则级变更属 Enterprise）。**CE 侧设计决策**：面板记录本工作流的生命周期事件（启用/停用/再启用），使 Business 档下历史功能有可读数据；每条=动作（如「启用了工作流」「停用了工作流」「重新启用了工作流」，CE 同构文案沿用，出处=58 §1.2 活动面板句式「X created the automation」+ zh 实录动词风格）+ 操作人 + 时间。动作标签 CE 侧定义并在 en 侧标 TODO(cloud-en)。
- 面板列表分页拉取（后端分页端点，见技术方案）。

## 3. 行为与状态机

| 状态       | 页面呈现                          | 可做                   | 后端效果                                                      |
| ---------- | --------------------------------- | ---------------------- | ------------------------------------------------------------- |
| 未启用     | 门卡（开关=关）                   | 翻开关（ADMIN/MEMBER） | 建 Workflow 行（is_active=True）+ 历史「启用」                |
| 启用       | 开关=开 + Default Workflow 表格行 | 禁用 / 查看历史        | —                                                             |
| 禁用（关） | 回到门卡形态                      | 再翻开关=再启用        | 同一行 is_active 置回 True + 历史「重新启用」（不新建第二行） |

- 单一工作流不变量：项目至多一条 Workflow 行（Business=单一 Default Workflow，58 §1.3）；禁用不删行、再启用复用原行（Default Workflow 身份与历史延续）。
- 历史记录内容：每次启停均留痕（操作人/动作/时间/备注=空）。云端不留痕启停（历史空因 Business 无变更源），CE 为让功能可用而记生命周期事件——已在 §2.5 声明为 CE 设计决策。

## 5. 验收用例（GWT，A=API / E2E 由子 PM 部署后冒烟执行）

| #    | Given                   | When                        | Then                                                                |
| ---- | ----------------------- | --------------------------- | ------------------------------------------------------------------- |
| W-1  | 项目未启用工作流        | GET 工作流列表（成员）      | 200 且数组为空（门卡语义：可读空态，不报错）                        |
| W-2  | 项目未启用工作流        | ADMIN/MEMBER 翻开关调用启用 | 200；产生 1 条 Default Workflow（is_active=True）+ 1 条历史「启用」 |
| W-3  | 工作流已启用            | 再次调用启用                | 400（不产生第二行、不重复写历史）                                   |
| W-4  | 工作流已启用            | GET 列表                    | 恰 1 行：name=Default Workflow、is_active=True                      |
| W-5  | 工作流已启用            | 行菜单禁用（确认后）        | is_active=False + 1 条历史「停用」；页面回门卡                      |
| W-6  | 工作流已禁用            | 再次调用禁用                | 400                                                                 |
| W-7  | 工作流已禁用            | 翻开关再启用                | 同一行 is_active=True + 1 条历史「重新启用」（行总数仍=1）          |
| W-8  | 启用→禁用→再启用各 1 次 | GET 更改历史                | 3 条按时间倒序：动作/操作人/时间齐全                                |
| W-9  | GUEST 项目成员          | 调用启用/禁用               | 403；GET 列表 200（与 Step01 口径一致：读三角色）                   |
| W-10 | 非该项目成员的登录用户  | GET/POST 该项目工作流       | 404/403（项目隔离，不可越权）                                       |
| W-11 | 未登录                  | 任意工作流端点              | 401                                                                 |
| W-12 | 项目 A 已启用           | 项目 B 列表/详情            | 项目 B 看不到项目 A 的行（单项目作用域）                            |

E2E 冒烟锚点（部署后由子 PM 执行）：门卡文案逐字 → 翻开关 → toast 逐字 → 表格四列值逐字 → 行菜单两项逐字 → 历史面板有启用记录 → 禁用（有确认）→ 回门卡 → 再启用 → 历史 3 条。
