> **重要口径**：按类型区分状态在 thinkym Business 试用里**没有可对照的界面**——Business 实测是全类型共用一套项目状态 / 一条 Default Workflow（58 号 §1.3），「多工作流绑类型」属 Enterprise Grid 档（12 号「default + 按类型的多条自定义 workflow」）。因此**本段不能声称与云端像素级对齐**，采用章程 §3 段 5 的推荐模型：**保留项目级状态池，由类型选择/限制「该类型可用的状态」**，不另造一套完整 Jira 状态机。凡属 CE 自行设计的，在 §3 假设清单里逐条声明假设、依据与错误的后果。

## 1. 目标与非目标

**目标**：在段 1 工作流壳与段 3 流转规则之上，补齐「类型 → 可用状态集合」的最小可用闭环：

1. ADMIN/MEMBER 可以在**类型详情页**为某个类型配置「可用状态」集合（从项目状态池中挑选）。
2. **空集合 = 继承项目全量状态池**（向后兼容：现网所有类型/数据零影响，行为与今天完全一致）。
3. 配置后，工作项的**新建、切换类型、改状态**三处走后端强校验：目标状态必须在该类型的可用集合内；被拒时返回可读错误并在前端回滚 + 提示。
4. 与段 3 流转规则**叠加生效**（串联校验，先可用集合后流转规则，错误码区分）。
5. **不新建任何状态实体**——复用既有项目级 `State` 池（章程红线：不出现第二套状态体系）。

**不做（本段明确排除）**：

- **多套工作流 + 按类型绑定工作流**（AU-06 / Enterprise Grid 档，12 号「default+按类型的多条自定义 workflow」；章程 §4 无界面口径）。本段仍只有一条 Default Workflow，类型差异化落在「可用状态集合」上。
- **完整 Jira 状态机 / workflow scheme**（章程段 5 明确不做）。
- **每状态「允许新建工作项」开关**（12 号 Build 一节有此开关，属工作流构建面；本段不做，见假设 A5）。
- **切换类型时自动迁移状态**到新类型默认/就近状态（官方 EG「切换 workflow 时不在新工作流内的状态上的工作项移到 fallback 状态（有预览）」，12 号；自动迁移涉数据变更+预览确认弹窗，超出本段最小闭环，见假设 A4）。
- 类型间的状态**映射/迁移预览**界面（同上，EG 档）。
- 段 3 已排除项不变：审批流、by/with 维度、Runner 脚本、外部 API v1 校验对称化。

## 2. 用户可感知行为

### 2.1 配置界面在哪（与云端的差异声明）

云端 Business 档**没有任何按类型区分状态的配置界面**（58 号实测全类型共用状态；类型详情页只有属性配置），因此本段 UI 是 **CE 自行设计的最简形态**：

- 位置：项目设置 → 工作结构 → 类型详情页（段 1 Step01 已有页），在「属性」区之下新增**「可用状态」配置区**。
- 形态：项目状态池的状态列表（色点 + 名称 + 分组），逐项勾选；顶部说明文案「未勾选任何状态时，该类型可使用项目的全部状态」。勾选至少一个状态后，仅被勾选状态对该类型可用。
- 保存：显式「保存」按钮；保存成功 toast「可用状态已更新。」（CE 自拟，标假设 A7）。清空全部勾选并保存 = 恢复继承全量。
- 权限：ADMIN/MEMBER 可编辑；GUEST 只读（§5）。
- 类型处于**停用**状态时配置区仍可读可写（配置独立于类型启停；类型启用后即生效）。

### 2.2 配置生效后谁能做什么

- **未配置（空集合）**：所有类型可用状态 = 项目全量状态池，行为与今天完全一致（现网数据零迁移零影响，假设 A2）。
- **已配置**：
  - **新建**：状态选择下拉按所选类型过滤（前端），显式提交了不在该类型可用集合内的状态 → 后端 400 拒绝（正/拒路径见 §6）。未显式选择状态时沿用项目默认状态，不做拦截（假设 A6）。
  - **改状态**（详情下拉 / 看板拖卡 / 批量面板，同一 PATCH 端点）：目标状态不在该工作项当前类型的可用集合内 → 400 拒绝，界面回滚 + toast。
  - **切换类型**：新类型的可用集合不包含该工作项当前状态 → 400 **拒绝**（不自动迁移，假设 A4）；界面回滚 + toast 提示「先调整状态再切换类型」或反向操作。前端状态下拉与类型切换提示联动。
- **状态下拉过滤**：详情页与新建弹窗的状态下拉按类型过滤选项（可用集合为空 = 不过滤）；被过滤掉但恰为当前值的状态仍显示（否则详情页会显示空白），后端兜底校验。

### 2.3 被拒时的界面提示

- 400 错误体带 `code=issue_type_state_not_allowed` 与类型名/状态名；前端复用段 3 的拒绝处理形态（乐观更新回滚 + 错误 toast）：
  - 改状态被拒：「无法使用状态『<状态名>』：类型『<类型名>』的可用状态不包含它。」
  - 切换类型被拒：「无法切换到类型『<类型名>』：该类型的可用状态不包含当前状态。」
  - （均为 CE 自拟文案，标假设 A7；无云端逐字文案可复刻。）
- 与段 3 流转规则被拒的 toast 同形态、不同错误码，用户能区分「类型不允许」与「流转规则不允许」。

## 4. 数据模型要点

- **不新建状态实体，不改 `State`**（章程红线）。扩展在项目桥：`ProjectIssueType.states` 多对多引用 `State`（blank=True），Django 自动建 through 表 `project_issue_type_states`。需要新迁移（0129）。
- 选 M2M 关系表而非 JSON 字段：FK 约束状态引用有效性；可查询（详情/新建过滤可 join）；软删陈旧引用由查询过滤 + 全量替换丢弃（A9）。评估详见技术方案 §1.1。
- 与段 1 `Workflow`/段 3 `WorkflowTransition` 的关系：互不引用。本段集合挂在类型桥上，段 3 规则挂在 Default Workflow 上——Business 档两者共存于同一项目但语义不同轴（「哪些状态可用」vs「状态间怎么流转」）。
- 类型删除（桥删除）→ M2M 关联行随 through 表级联清理，无残留。
- 本段无更改历史要求（可用状态变更不写 WorkflowChangeLog——那是工作流的历史；类型配置历史不在段 1 壳的覆盖范围，列 §7）。

## 6. 验收用例（Given/When/Then，≥10 条，正/拒路径各 ≥2）

1. **G** 项目状态池含 Backlog/Todo/In Progress/Done/Cancelled，类型 Task 未配置可用状态 **W** 成员新建 Task 并显式选 Done **T** 成功（空集合 = 继承全量，正路径 1，A2）。
2. **G** 同上 **W** 成员把 Task 的可用状态配置为「Todo / In Progress / Done」并保存 **T** toast「可用状态已更新。」，重新打开配置区勾选保持（正路径 2）。
3. **G** Task 可用状态已配置为「Todo / In Progress / Done」 **W** 成员在新建弹窗选 Task 后打开状态下拉 **T** 下拉只出现这 3 个状态（前端过滤）。
4. **G** 同上配置 **W** 用 API 直调 POST 新建 Task 且 state=Cancelled **T** 400，`code=issue_type_state_not_allowed`，工作项未创建（拒路径 1，后端强校验）。
5. **G** 同上配置，已有 Task 工作项当前状态 Todo **W** 成员在详情页把状态改到 Cancelled **T** 请求 400，界面回滚，toast「无法使用状态『Cancelled』…」（拒路径 2，A7）。
6. **G** 同上配置 **W** 成员把该 Task 从 Todo 改到 In Progress **T** 成功且状态活动留痕与既有行为一致。
7. **G** 同上配置，已有 Epic 工作项当前状态 Done（Epic 未配置可用状态=继承全量） **W** 成员把 Epic 的类型切成 Task（Task 集合含 Done） **T** 切换成功。
8. **G** Task 可用状态=「Todo / In Progress」，已有 Epic 工作项当前状态 Done **W** 成员在详情页把该工作项类型切成 Task **T** 400 拒绝，类型未变，toast「无法切换到类型『Task』：该类型的可用状态不包含当前状态」（A4 拒绝式切换）。
9. **G** 类型可用集合配置了 Done，工作流流转规则未配置 **W** 成员把该类型工作项改到 Done **T** 成功（只有集合校验，段 3 规则不命中，A3 串联第一环）。
10. **G** 类型可用集合含 In Progress，且段 3 规则配「Todo → 仅 In Progress」 **W** 成员把该类型工作项从 Todo 改到 In Progress **T** 成功（两环都过，叠加正例）。
11. **G** 类型可用集合含 Done，段 3 规则配「Todo → 仅 In Progress」 **W** 成员从 Todo 改到 Done **T** 400 `code=workflow_transition_not_allowed`（过集合、被流转规则拦，A3 错误码区分）。
12. **G** ADMIN 打开类型详情配置区 **W** 保存可用状态 **T** 成功；GUEST 打开同页 **W** 尝试保存 **T** 不可编辑；直调 API 返回 403（A8）。
13. **G** 项目 A 的类型配置 **W** 用项目 B 的状态 id 调 A 项目的 states 端点 **T** 400（跨项目状态拒绝），不泄露跨项目数据。
14. **G** 配置中含状态 S，S 随后被软删除 **W** 成员把该类型工作项改到另一集合内状态 **T** 校验按「剔除已删状态」的集合生效，不报错（A9）。

## 7. 不在本段做的项

- 多套工作流 / 按类型绑定工作流（AU-06 / EG）。
- 每状态「允许新建工作项」开关（A5：粒度在「状态」轴，与本段「类型→集合」不同轴）。
- 切换类型自动迁移状态 + 预览确认（EG fallback 机制，A4）。
- 类型配置更改历史（WorkflowChangeLog 是工作流域的历史；类型域无历史面板，加历史列 §7 后续）。
- 保存类型时「默认状态不在集合内」的配置期警告（A6 的后续改进项）。
- 外部 API v1 work items 路径的校验对称化（同段 3 口径，挂载点在技术方案记录）。
- 批量改状态面板的独立校验路径（批量走同一 PATCH 端点，自动获得校验；独立 bulk 端点不挂）。
- 状态映射/可视化集合关系图。
