# 03. 段 3 产品方案 — 流转规则（谁可以把工作项迁移到哪些状态）

> 状态：已确认（段内自决，D64 授权）｜2026-11-17｜产品 zcode 落盘。
> 章程锚点：[00.子项目章程](../项目管理/00.子项目章程.md) §3 段 3、§5 段 3 验收；[01.zcode连续分段提示词](../项目管理/01.zcode连续分段提示词.md) §段 3 最低要求。
> 对标资料：[12.自动化工作流与Runner](../../01.功能调研/14.官方文档逐功能摘要/12.自动化工作流与Runner.md)（官方 Workflows 文档摘要，下称「12 号」）、[58.自动化与工作流深测/对比.md](../../01.功能调研/58.自动化与工作流深测/对比.md)（下称「58 号」）、[99.勘误与权威结论表](../../01.功能调研/99.勘误与权威结论表.md) AU-05。
> **重要口径**：流转规则在 thinkym Business 试用里**没有可对照的配置界面**（规则编辑属 Enterprise 档，58 号 §1.3 边界行实测），因此**本段不能声称与云端像素级对齐**。凡有官方文档/实录依据的逐条标注；凡属 CE 自行设计的，在 §3 假设清单里逐条声明假设、依据与错误的后果。

## 1. 目标与非目标

**目标**：在段 1 工作流壳（启用门卡 + Default Workflow 行 + 更改历史）之上，补齐流转规则的最小可用闭环：

1. ADMIN/MEMBER 可以在 Default Workflow 上配置「状态 → 允许流转到的状态集合」规则。
2. 规则启用期间，工作项状态变更走后端强校验：不在允许集合内的迁移被拒绝，并给出可读的错误说明。
3. 规则的每次变更写入 WorkflowChangeLog，更改历史面板可见「流转规则更新」事件。
4. 未配置任何规则时行为与今天完全一致（全部允许）——对段 0/1/2 零回归。

**不做（本段明确排除）**：

- **审批流**（章程 §4 已拍板不做；官方审批流属 Enterprise，12 号「Approval flow（EG）」）。
- **完整 Jira 式状态机**（workflow scheme、按类型多工作流绑定等，章程段 5 也不做，本段更不做）。
- 流转的 **by（成员名单）维度**：官方 Transition flow 是「move to + by（默认 All 成员）+ with（条件）」三元组（12 号），Business 档默认 All 成员且试用中未见成员名单入口；本段只实现 move to（状态关系）维度，by/with 列入 §7。
- 每状态「允许新建工作项」开关（官方 Build 一节有此开关，12 号；属段 5「按类型区分状态」的相邻能力，本段不做）。
- Runner Pre-validation 脚本（Enterprise，12 号）。
- 拖卡「卡片弹回」动画级还原（官方 EG 实录为拖卡弹回+提示，12 号「非法迁移被拦截并提示」；CE 拖卡本身有乐观更新回滚，本段做到「回滚 + toast」为止，不做动画）。

## 2. 用户可感知行为

### 2.1 规则配置界面在哪（与云端的差异声明）

云端 Business 档**没有任何规则配置界面**（58 号 §3.6 步骤 6：状态页行菜单无流转规则入口；工作流页 Default Workflow 只读），规则编辑属 Enterprise。因此本段 UI 是 **CE 自行设计的最简形态**，与云端无对照：

- 位置：项目设置 → 工作结构 → 工作流页，Default Workflow 行**行内展开**（行右侧新增「流转规则」展开按钮），不新开详情页——与段 1「行主体不可点击进详情（云端点行无响应）」的实录保持兼容，展开是 CE 增量。
- 形态：展开后为「状态 × 允许移动到」多选列表。每行 = 项目状态池中的一个状态（名称+色点）+ 一个多选下拉（该状态允许移动到的其他状态，不含自身）。空选 = 该状态不受限（见假设 A2）。
- 保存：显式「保存」按钮（批量修改后一次提交）；保存成功 toast「流转规则已更新。」（CE 自拟，标假设 A7）。
- 权限：ADMIN/MEMBER 可展开可编辑；GUEST 不可展开（§5）。

### 2.2 启用工作流后谁能改什么

- **未启用工作流 / 已启用但未配置任何规则**：行为与今天完全一致——所有项目成员按既有权限改状态，无任何新限制（假设 A2）。
- **已启用且配置了规则**：此后所有走「编辑工作项」的状态变更（详情页下拉、看板/列表拖卡、批量面板走同一 PATCH 端点）都受校验：从状态 X 只能移动到 X 的允许集合内状态；**没有出现在规则里的源状态不受限**（假设 A2 的精确化）。
- 校验对**所有人**生效（含 ADMIN）——规则是项目级结构约束，不是个人偏好（假设 A5）。云端 ADMIN 是否豁免无资料，若假设错误的后果见 A5。

### 2.3 流转被拒时的界面提示

- 拖卡/下拉改状态被后端 400 拒绝时：界面回滚到原状态（既有乐观更新回滚路径，不改）+ 错误 toast：「无法移动：不允许从『<源状态>』移动到『<目标状态>』（受工作流规则限制）。」（CE 自拟文案，标假设 A7；官方 EG 实录只有「非法迁移被拦截并提示（拖卡时卡片弹回）」一句，无逐字文案可复刻，12 号「运行规则」）。
- 提示中带源/目标状态名，用户能直接看懂该找谁改规则；本段不在 toast 里加「去配置」跳转（列 §7）。

## 4. 数据模型要点

- **新增表 `WorkflowTransition`**（评估见技术方案 §2，选关系表而非 Workflow JSON 字段）：`(workspace, project, workflow FK, from_state FK, to_state FK)`，唯一约束 `(workflow, from_state, to_state)`；状态删除级联删除规则行。需要新迁移（0128，含 WorkflowChangeLog.action choices 扩展）。
- 与项目状态池的关系：**不复制、不新建状态**——规则只引用既有 `State` 行（章程 §5「保留项目级状态池」）。
- 与工作项类型的关系：本段规则**不区分类型**（Default Workflow 覆盖所有工作项类型，58 号 §1.3「所有工作项类型」列）。
- 规则变更留痕：复用 `WorkflowChangeLog`，`action` 新增 `transition_rules_updated`，note 记规则条数摘要。

## 6. 验收用例（Given/When/Then，≥10 条，正/拒路径各 ≥2）

1. **G** 项目已启用工作流且未配置规则 **W** 成员把工作项从 Todo 移到 In Progress **T** 成功，行为与未启用工作流一致（A2）。
2. **G** 已配置规则「Todo → 只能到 In Progress」 **W** 成员把工作项从 Todo 移到 Done（详情页下拉） **T** 请求 400，界面回滚，toast 提示「不允许从『Todo』移动到『Done』」（拒路径 1）。
3. **G** 同上规则 **W** 成员拖看板卡片从 Todo 到 In Progress **T** 成功且状态留痕（活动记录）与既有行为一致（正路径 1）。
4. **G** 规则只配了「Todo → In Progress」 **W** 成员把工作项从 In Progress 移到 Done **T** 成功（In Progress 无规则条目，不受限，A2 精确化）。
5. **G** 工作流已停用 **W** 成员把工作项从 Todo 移到 Done（虽有规则残留） **T** 成功（停用暂停执行，官方「停用暂停执行不丢配置」，12 号）。
6. **G** ADMIN 打开工作流页展开流转规则 **W** 为 Todo 勾选 In Progress 并保存 **T** toast「流转规则已更新。」，重新展开可见勾选保持（正路径 2）。
7. **G** 同上保存后 **W** 打开更改历史面板 **T** 最新一条为「流转规则更新」（A3）。
8. **G** MEMBER 打开同一面板 **W** 保存规则 **T** 成功（ADMIN/MEMBER 均可配，§5）。
9. **G** GUEST 访问工作流页 **W** 尝试展开/PUT 规则 **T** 不可展开；直调 API 返回 403（拒路径 2）。
10. **G** 已配置「Todo → In Progress」 **W** 用 API 直调 PATCH 把 state 改到 Done **T** 400 且 issue 的 state 未变、无 state 活动记录产生（后端强校验，不依赖前端）。
11. **G** 规则含「Todo → In Progress」 **W** ADMIN 把 In Progress 状态从项目状态池删除 **T** 该规则行被级联删除，不再生效（A6）。
12. **G** 项目 A 的规则 **W** 用项目 B 的成员/状态调用 A 的规则端点 **T** 403/400，不泄露跨项目数据。

## 7. 不在本段做的项

- 审批流、审批人（Approve/Reject）按钮。
- 流转的 by（成员名单）/ with（条件）维度。
- 每状态「允许新建工作项」开关。
- 按工作项类型区分规则 / 多套工作流（EG 档；段 5 另议）。
- Runner Pre/Post 脚本。
- 自动化引擎触发的状态变更校验（CE 无自动化引擎）。
- 外部 API（`/api/v1/` work items）路径的校验对称化——本段只覆盖 app API 的 issue PATCH，外部 API 挂载列为后续事项（在技术方案记录挂载点，供后续沿用）。
- toast 内「去配置规则」跳转、规则可视化 DAG 图。
