# 06. 段 6 产品方案 — 时间跟踪功能开关接线（TM-01）

> 状态：已确认（段内自决）｜2026-11-17｜产品 zcode 落盘。
> 依据：[P0-10 brief](../../01.功能调研/16.改造切入点/P0-10-时间跟踪开关接线.md)、[56 号时间跟踪与工作日志对比](../../01.功能调研/56.时间跟踪与工作日志/对比.md)、[子项目章程 §3 段 6 / §5](../项目管理/00.子项目章程.md)。

## 1. 目标与边界

把项目功能设置里的「时间跟踪」开关接通：`Project.is_time_tracking_enabled` 字段从「无 UI 消费」变为可管理，开关字段落库、刷新保持。

**做**：设置 → 功能（Features）出现「时间跟踪」开关项，与既有五个功能开关（周期/模块/视图/页面/接收）同形态；PATCH `is_time_tracking_enabled` 落库。

**不做**（TM-02/03，56 号 D-01/D-03~D-08，本段明确排除）：

- 工时记录模型/端点（IssueWorklog 全链路）；
- 工作项详情「记录工时」弹窗、工作日志 tab、Tracked time 属性；
- 项目设置「工作日志」工时表页与 Excel/CSV 导出。

**预期管理（P0-10 §9.1）**：开关描述文案不承诺详情页会出现任何工时入口；开关打开后详情页无变化是预期行为，记录功能随后续版本提供。

## 2. 开关位置与形态

| 项   | 决策                                                                                                                       | 依据                                                                            |
| ---- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 位置 | 项目设置 → 功能分组（Features）新增「时间跟踪」子页，侧栏导航与周期/模块/视图/页面/接收并列                                | CE 现有功能开关均为 `features/<名>` 子页（56 号 3.4：CE 导航为 功能 组）        |
| 形态 | 单开关卡片「启用时间跟踪」+ 说明文案，复用 `ProjectSettingsFeatureControlItem`（与既有五个开关同控件同交互）               | 云端同为单卡片开关（56 号 1.1 步骤 4）；CE 同形态就近                           |
| 权限 | 仅项目 ADMIN 可见/可翻（同既有五个功能子页的 `EUserPermissions.ADMIN` 门槛与侧栏 `EUserProjectRoles.ADMIN` access）        | 云端同角色门槛；P0-10 验收 4                                                    |
| 落库 | 翻开关即 PATCH `/api/workspaces/{slug}/projects/{id}/` `{"is_time_tracking_enabled": <bool>}`，toast 成功/失败沿用现有文案 | 云端翻开关即 toast「Project feature updated successfully.」（56 号 3.1 步骤 5） |

## 3. 文案（zh 用 56 号云端实录；en 为源，标来源）

- en（源）：
  - 标题/导航：`Time tracking`
  - 页面说明：`Track time on work in this project and adjust it per project.`
  - 开关标题：`Enable time tracking`
  - 开关描述：`Allow project members to log time on work items.`
- zh-CN（56 号 3.1 步骤 4 云端实录直译，与云端文案逐字对应）：
  - 标题/导航：`时间跟踪`
  - 开关标题：`启用时间跟踪`
  - 开关描述：`允许项目成员在工作项上记录工时。`
- zh-TW：繁体同文（`時間追蹤` / `啟用時間追蹤` / `允許專案成員在工作項上記錄工時。`）。
- 其余 19 个 locale：追加同键、英文文案兜底，标 `TODO(cloud-en)`（同段 1/3/5 口径）。
- 页面说明文案（description）云端无对应项，自拟对齐既有功能页形态，标 A1 假设。

## 4. 假设清单

- **A1**：云端功能子页仅有一句开关描述（56 号 1.1），无独立页面级 description；CE 既有五个功能子页均有页面级 `description`，为保持同构自拟一句，属展示层假设，不影响功能。
- **A2**：开关默认关闭（后端 `default=False`，与云端一致），不随项目创建弹窗选择（创建弹窗功能选择不在本段范围）。

## 5. 验收（GWT）

1. Given 项目 Admin 打开项目设置 → 功能分组，When 展开导航，Then 出现「时间跟踪」项（与 周期/模块/视图/页面/接收 并列）。
2. Given 项目 Admin 打开「时间跟踪」设置页，Then 出现单开关卡片「启用时间跟踪」与描述「允许项目成员在工作项上记录工时。」（zh），开关初始状态与库中 `is_time_tracking_enabled` 一致（新项目默认关）。
3. When 翻开开关，Then toast 成功，`is_time_tracking_enabled=true` 落库，刷新后开关仍为开。
4. When 再次关闭开关，Then `is_time_tracking_enabled=false` 落库，刷新保持。
5. Given 非 Admin 成员（MEMBER/GUEST），When 访问「时间跟踪」设置页，Then 无权限视图（与既有功能子页一致）。
6. Given API 直调 `PATCH .../projects/{id}/ {"is_time_tracking_enabled": true}`，Then 200 且 GET 可读回 true（字段 serializer 已暴露，回归验证）。
7. Given 开关已打开，When 打开任一工作项详情，Then 不出现工作日志 tab / 记录工时按钮 / Tracked time（明确边界：记录功能属 TM-02/03，本段不做）。
8. Given 开关反复切换，When 回到功能设置同屏查看其余五个开关（周期/模块/视图/页面/接收）与工作结构（类型/状态/工作流），Then 均不受影响（零回归）。
