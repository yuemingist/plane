## 1. 目标与非目标

**目标**：把段 2 的自定义属性贯穿到工作项列表三处——

1. 列表可显示自定义属性（显示属性菜单动态开关 + 行内紧凑渲染）；
2. 可按属性筛选（筛选菜单动态出现自定义属性项，控件按属性类型分派）；
3. 导出 CSV 含动态属性列（判定「做」，见 §4）。

**非目标（本段不做）**：

- 列表行内**编辑**属性值（编辑只在详情侧栏与新建/更新弹窗，段 2 已交付）；
- 按属性**排序**（云端实测未见属性排序列证据；57 号 §5-6 亦未测）；
- spreadsheet/甘特/日历布局的属性列（本段只做**列表布局**行渲染；筛选与导出不受布局限制）；
- 文本 / 数字 / URL / 富文本四类的**筛选控件**（见 §3 裁剪）；
- 视图（View）保存面板里的属性列持久化新面——视图 display_properties 复用同一 JSON 键，自动随存。

## 2. 列表列形态选型

云端形态（57 号 §3.4 步骤 10-11）：显示属性菜单是一个 chip 组，「工作项类型」是一颗 chip；未观察到「每个属性一颗 chip」的实测截图（云端启用属性后列表列形态无逐属性证据）。

**选型：动态逐属性开关（每颗 chip = 一个已启用属性），而非统一「自定义属性」单列**。理由：

1. 单列塞 8 类异构值（文本/多选 chips/布尔/日期）在一行内不可读，违背「紧凑形态」要求；
2. 逐属性开关与既有显示属性 chip 组 UI 同构（`display_properties` JSON 追加 `issue_property_<id>` 布尔键），实现成本与单列方案相当，且持久化面（ProjectUserProperty.display_properties）零迁移；
3. 行内只渲染**该工作项类型绑定的属性**（双门控：绑定 + 池级 is_active，沿用段 2 语义），未绑定该类型的行该列显示空。

**行内紧凑形态（对照 57 号 D-11 与详情侧栏控件）**：

| 属性类型   | 紧凑形态                                           |
| ---------- | -------------------------------------------------- |
| 文本 / URL | 截断文本（单行，hover tooltip 全文）               |
| 数字       | 数值文本（保留 decimal_places 千分位显示）         |
| 下拉       | 选项名 chips（单选 1 颗 / 多选 N 颗，截断收进 +N） |
| 布尔       | 是 / 否 chip                                       |
| 日期       | 格式化日期文本                                     |
| 成员       | 成员名 chips（单选 1 颗 / 多选 N 颗）              |
| 富文本     | 去标签截断文本                                     |

## 3. 筛选形态与控件裁剪

云端形态（57 号 §3.4 步骤 11）：筛选菜单含「自定义属性」入口，子菜单=已启用属性逐个可筛。

**追赶形态**：筛选下拉菜单直接出现项目已启用的自定义属性项（逐属性一颗，含类型图标），不再加「自定义属性」二级聚合层（与既有 Type/State 等平铺同级，实现面最小；差异已在方案声明）。筛选键 `customproperty_<属性id>`，值随属性类型分派：

| 属性类型                   | 控件      | 操作符 | 说明                                                                                                                          |
| -------------------------- | --------- | ------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 下拉                       | 选项多选  | in     | 单选/多选属性同控件；值=选项 id                                                                                               |
| 成员                       | 成员多选  | exact  | 值=成员 id                                                                                                                    |
| 日期                       | 日期选择  | exact  | 值=ISO 日期                                                                                                                   |
| 布尔                       | 是/否单选 | exact  | 值=true/false                                                                                                                 |
| 文本 / 数字 / URL / 富文本 | **不做**  | —      | 既有 rich filters 体系无文本输入控件（`EXTENDED_FILTER_FIELD_TYPE` 为空）；补文本控件属新组件面，超出本段最小集，裁剪记录于此 |

## 4. 导出判定：**做**

**结论：Business 有「导出含自定义属性」，本段做。**

依据链：

1. [65 号对比](../../../01.功能调研/65.通知内容与导出搜索/对比.md) §1.5：云端工作项导出 CSV **33 列**，实测文件（`thinkym-5b3a16ff-...csv`，2026-11-14）在固定列后**动态追加自定义属性列**（「调研-文本属性」「调研-下拉属性」两列，§1.5 列结构实录）；§3.3 步骤 6 全流程留档。
2. [57 号](../../../01.功能调研/57.工作项类型与自定义属性/对比.md) §5-6 曾标「导出暴露面未测」，由 65 号实测补齐，判据闭合。
3. [11.导入导出摘要](../../../01.功能调研/14.官方文档逐功能摘要/11.导入导出.md)：导出走工作区设置 → 导出（CE 已同构存在），列集固定无字段选择——即属性列应**自动追加**，不需要导出弹窗新增配置项。

**形态**：CSV/Excel/JSON 三格式沿用现有导出链路；每个**已启用**（is_active）属性自动成为一列（列名=属性名），值格式化（多值用 `|` 连接，与导入端自定义属性列解析规则对齐，可往返）；仅导出导出人可读工作项，权限面不变。

## 5. 顺手修复（段 3 P3 #9）

错误 toast 泄漏 ICU 占位符「错误！{count, plural, one {工作项} other {工作项}}更新失败」。根因：`apps/web/components/issues/issue-detail/root.tsx` 三处（更新失败/删除成功/删除失败）调用 `t("issue.label")` 未传 `count`，i18next-icu 对缺变量的 ICU 表达式回退原文，原文再被插值进 `common.entity.update.failed`。**修法**：调用点补 `{ count: 1 }`（与 `issue-detail/label/root.tsx` 既有用法同构），不改动共享键值，避免影响其他 `{entity}` 消费方；ICU 插件已配置（`packages/i18n/src/core/instance.ts:19`），故无需改 22 locale 键值。
