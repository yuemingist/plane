## 2. 套餐速查（2026-11-14 定价页口径）

与 [10 号文档](10.正式版功能清单-官方资料核实.md)一致，仅列时间线分析所需的最小集合：

## 5. 趋势分析（7 条，均有证据）

### 趋势 1：功能下放的主通道是「CE 大版本」，与云端同一主干，滞后 0–6 周 [推断]

- 证据链：云端 2025-10-31 changelog 的 Power K（[changelog](https://plane.so/changelog/2025-10-31-power-k-shortcuts-empty-states-pages)）与 12-01 新导航（[changelog](https://plane.so/changelog/2025-12-01-workspace-navigation-custom-forms-threads)）→ 12 天后出现在 **CE v1.2.0**（2025-12-11，[release](https://github.com/makeplane/plane/releases/tag/v1.2.0)）；云端 2026-01-07 "cleaner calmer" 视觉精修 → 3 个月后 CE v1.3.0 同主题（[release](https://github.com/makeplane/plane/releases/tag/v1.3.0)）；编辑器拖拽重建云端 10-21（[changelog](https://plane.so/changelog/26-10-20-plane-editor-rebuilt)）→ 预计随 v1.5.0 GA 下放。
- 结论：**CE 不是"功能孤儿"，是云端 trunk 的延迟快照**。追赶策略上，凡是"全套餐基础体验"类功能（导航/编辑器/筛选），等 1–2 个 CE 版本就能白拿，不必自己造。

### 趋势 2：新增高价值功能正在向高档位集中，且 2026-10 起官方显式标注档位 [确认]

- 证据链：2026-10 起每条 changelog 带 Availability 小节——Databases=Enterprise Grid（[10-25](https://plane.so/changelog/26-10-25-databases-arrive-in-plane)）、Work item security=Enterprise Grid（[10-26](https://plane.so/changelog/26-10-26-work-item-security-for-sensitive-work)）、Cascading properties=Enterprise Grid（[10-27](https://plane.so/changelog/26-10-27-cascading-properties-now-in-plane)）、Git development panel=Pro+（[10-30](https://plane.so/changelog/git-development-panel-in-plane)）；而基础体验类（编辑器重建）标注"全套餐"（[10-21](https://plane.so/changelog/26-10-20-plane-editor-rebuilt)）。
- 结论：官方在**用档位标注管理预期**：商业新功能不再承诺下放。追赶目标的"移动端"在向上漂移——M1 锁定 Business 层及以下即可，Enterprise Grid 独占（Databases/Audiences/Cascading）不值得投入。

### 趋势 3：对 CE 的「收回」主要发生在授权层与功能开关层，代码层少量存在 [确认+推断]

- 收回证据：① OIDC 在 v2 商业授权中被上锁，社区要求回归免费（[#8047](https://github.com/makeplane/plane/issues/8047)，2025-10-31，官方未回应）；② Active Cycles 在 CE 只渲染"升级营销组件"（本仓库实测截图 `docs/01.追赶正式版/01.功能调研/21.周期与里程碑/ce-workspace-active-cycles-2026-11-14.png`，后端聚合 API 仍在）；③ Milestones 在 CE 已移除（[21/对比.md](21.周期与里程碑/对比.md) D-05，web 组件与 issue 模型无 milestone 引用）；④ Bulk operations 在定价矩阵属 Pro（[10 号文档 §2.1](10.正式版功能清单-官方资料核实.md)）。
- 下放证据（平衡视角）：Intake 及其 Triage 状态进了 CE（v1.2.0）、Pages 实时协同服务 `apps/live` 在 CE 仓库内（v1.5.0-rc2 仍在加固其权限，[release](https://github.com/makeplane/plane/releases/tag/v1.5.0-rc2)）、Gitea 认证进了 CE（v1.3.0）。
- 结论：官方策略 = **"协作/表单类基础功能下放 CE，差异化企业功能（SSO/批量/周期视图）留在开关后"**。fork 侧应预期：CE 代码里"有后端无入口"的功能（如 active-cycles 聚合 API）是官方有意保留的商业开关，不是 bug——自开风险自担（上游升级可能覆盖）。

### 趋势 4：自托管被重新定位为企业卖点，商业自托管（Prime/Commercial/Airgapped）才是官方 self-host 投入方向 [确认]

- 证据链：2026-09~10 集中发布 air-gap/主权叙事博客——[数据主权](https://plane.so/blog/how-enterprises-manage-projects-with-full-data-sovereignty)（09-10）、[主权工作基础设施](https://plane.so/blog/sovereign-work-infrastructure-the-case-beyond-cloud-only-software)（09-17）、[air-gap 指南](https://plane.so/blog/the-complete-guide-to-air-gapped-project-management)（09-18）、[Airgapped 授权与离线升级](https://plane.so/blog/how-plane-airgapped-licensing-and-offline-upgrades-work)（10-09）、[K8s 生产指南](https://plane.so/blog/self-hosted-plane-on-kubernetes-a-production-guide)（10-09）；定价页 Self-hosted tab 与云端同构四档；MS Teams 集成明确"self-hosted 可用"（[10-20](https://plane.so/blog/plane-now-connects-to-microsoft-teams)）。
- 同时 CE 的 v1.4.x 系列几乎全是**安全与实例运维**修复（租户隔离、air-gap 恢复、成员恢复 CLI、实例日志 Postgres 化）——CE 被定位为"能安全自跑的底座"，而不是"功能完整的免费版"。
- 结论：fork 追赶不需要担心"CE 被废弃"，但**不要指望官方把商业自托管的功能代码开源**；我们与"商业自托管用户"是竞争关系，与 CE 上游是共生关系。

### 趋势 5：云端自己在迭代「未落地功能」，Milestones/Releases 是进行时 [确认]

- Milestones：云端项目设置存在功能开关但 `/milestones/` 路由 404（本仓库实测：[21/对比.md](21.周期与里程碑/对比.md) + 截图 `cloud-project-milestone-feature-settings-2026-11-14.png`）；2026-08-14 changelog 已把 **milestones 纳入自动化动作**（[changelog](https://plane.so/changelog/2026-08-14-collapsible-toggle-blocks-dashboard-intake-widgets)）；后续 bug 修复出现"按 cycle 与 milestone 分组计数"（[08-31 增强项](https://plane.so/changelog/2026-08-31-shared-views-tabs-in-pages-and-more) 修复清单）。
- Releases：新模块成型中——发布管理博客（[10-19](https://plane.so/blog/how-to-plan-and-ship-releases-in-plane)）、自动化动作（同上 08-14）、"Releases 支持搜索/筛选/排序"（[08-31](https://plane.so/changelog/2026-08-31-shared-views-tabs-in-pages-and-more)）、release picker（[10-31 修复清单](https://plane.so/changelog/26-10-31-page-subscribers-widgets-in-pages-and-more--31-oct-2026)）。
- 结论：云端在为"发布/里程碑"这类**时间锚点型组织对象**铺数据模型（自动化先行、UI 后到）。M1 **不建**这两个实体，但工作项外键设计应避免用死"只能挂 cycle/module"，留扩展位（R5 技术方案时落实）。

### 趋势 6：API/SDK 版本差在拉大，前端底座差在收窄 [确认]

- API：云端开发者文档已主推 **API v2**（bulk 批量端点、sparse fields、upsert、workspace 级资源、迁移指南，[v2 introduction](https://developers.plane.so/api-reference/v2/introduction)）；CE 仓库仅暴露 `api/v1/`（本仓库 `apps/api/plane/urls.py` 第 22 行，无 v2 挂载）。官方 Node SDK 12 个月发 24 版（0.1.0 2025-06-20 → 0.3.1 2026-09-22，[npm](https://www.npmjs.com/package/@makeplane/plane-node-sdk)），主要围绕云端新能力；而 MCP server 停更 12 个月（最后发版 0.1.5，2025-10-30，[npm](https://www.npmjs.com/package/@makeplane/plane-mcp-server)）。
- 前端：`@makeplane/propel` 2026-07-06 首发，4 个月 28 个版本至 0.9.9（[npm](https://www.npmjs.com/package/@makeplane/propel)），并已在 CE v1.5.0-rc1 全面接入——CE 与云端共享同一设计系统。
- 结论：**做 API/自动化集成时不要照抄云端 v2 文档**（CE 无对应端点）；做 UI 时尽量贴 propel 以减小与上游的 diff。

### 趋势 7：前端大迁移约一年一次，fork 同步成本必须按此预算 [确认]

- 证据链：v1.2.0（2025-12-11）Next.js→React Router+Vite（[release](https://github.com/makeplane/plane/releases/tag/v1.2.0) + [博客](https://plane.so/blog/why-did-we-migrate-plane-from-nextjs-to-react-router-vite)）；v1.5.0-rc1（2026-11-10）React 19 + React Router 8（[release](https://github.com/makeplane/plane/releases/tag/v1.5.0-rc1)）。中间穿插 admin 迁 propel、i18n 机制更换（v1.4.0 react-i18next）。
- 结论：与上游的同步窗口应避开 rc 期、在 GA 后 1–2 周内完成；每次大版本（x.y.0）前**不要**在 fork 里做大面积 UI 重构，否则冲突成本指数级上升。2025-11、2026-06、2026-09 是官方"空窗月"（无 CE release），是 fork 自研功能的安全窗口。

## 6. 官方近期动向对 M1 的影响 Top 5

1. **安全同步是底线，v1.4.3 与 v1.5.0-rc2 必须尽快吸收**：v1.4.3 的租户隔离修复（发布页跨项目写入、子工作项越权读取）与 rc2 的 live socket 权限校验，直接决定"自部署 + 对外提供"场景是否安全。按 [08.工作约定](../../项目管理/08.工作约定.md)，由明哥决定同步窗口。
2. **propel 设计系统进入 CE，M1 UI 直接押注它**：CE v1.5.0-rc1 已把 web/admin 切到 `@makeplane/propel`；自研组件若仍基于旧 `@plane/ui` 会在下一次同步时大量冲突。UI 追赶（文档 20 系列）的组件选型全部换成 propel。
3. **React 19 + RR8 是 fork 自定义代码的最大破坏性变更**：v1.5.0-rc1 升级了运行时（dropdowns 已出现 headlessui v2 回归，[PR #9694](https://github.com/makeplane/plane/pull/9694)）。fork 内已有的自定义改动需要在 v1.5.0 GA 同步时集中回归；在 GA 前冻结大规模 UI 改动。
4. **权限与类型系统按云端终态建模**：云端 04-25 两段式权限（角色+权限方案）与 05-31 "Epics 并入工作项类型"是数据模型终态信号。M1 的工作项类型（文档 51）与权限表结构按该方向预留，避免二次翻修。
5. **i18n 已切 react-i18next 命名空间（v1.4.0）**：中文包工作必须挂在 `packages/i18n/src/locales/zh/` 新机制上（19 语言基线，AGENTS.md 翻译流程同源）；旧的单文件 TS 翻译方式作废。
