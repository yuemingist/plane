# 官方动向监控方案（周执行手册）

> 状态：生效｜编写日期 2026-11-14｜任务编号：R9
> 执行者：Plane助理（或任何接手人）。**基线数据见主文档 [../15.官方Release与路线图跟踪.md](../15.官方Release与路线图跟踪.md)。**
> 铁律（继承 08.工作约定）：**本方案所有命令只做"读取上游公开数据"（GitHub API / 官网 / npm registry），绝不执行 `git fetch`、不修改 `~/Develop/plane` 内任何源码与分支**；脚本只写临时目录或 stdout。

## 1. 监控对象与频率总表

| #   | 监控对象                      | 频率                                       | 方式                               | 信号含义                                                                            |
| --- | ----------------------------- | ------------------------------------------ | ---------------------------------- | ----------------------------------------------------------------------------------- |
| A   | upstream `preview` 功能性提交 | **每周一**                                 | GitHub commits / compare API       | 新功能先于 release 出现在 preview；`feat:`/`fix:` 与 `WEB-*/GIT-*` 工单号是风向前标 |
| B   | GitHub Releases（CE 版本）    | **每周一** + 周四复查                      | GitHub releases API                | `rc` 出现 = 1~4 周内 GA；GA = 触发"是否同步上游"决策（提醒明哥，见 08 工作约定 §1） |
| C   | plane.so/changelog（云端）    | **每两周**（官方双周节奏），周一顺带瞄一眼 | changelog sitemap diff             | 云端新功能与 Availability 标注 = 套餐归属变化                                       |
| D   | 定价页套餐矩阵                | **每月一次**                               | 正文 hash 对比 + 人工读差异        | 档位/价格/功能归属变化直接影响追赶目标                                              |
| E   | 官方 SDK/组件包版本           | **每周一**                                 | npm view                           | propel / node-sdk / mcp-server 三个包                                               |
| F   | 官方博客产品公告              | **每两周**                                 | blog sitemap diff                  | 产品级公告（新模块、商业策略）                                                      |
| G   | 论坛与状态页                  | **每月一次**人工                           | forum.plane.so、status.plane.so    | 社区风向；云端故障是否影响自托管版本发布节奏                                        |
| H   | 云端未落地功能复测            | **每月一次**人工                           | 登录云端实测（按 21/对比.md 方法） | Milestones `/milestones/` 路由是否落地；Active Cycles 形态变化                      |

频率依据：官方 changelog 是双周节奏（2026 年全部条目间隔 12–17 天，见主文档时间线）；CE release 间隔 1–12 周（v1.2.x→v1.3.0 约 6 周一个 minor，patch 安全版随时插队）；preview 几乎每天都有提交。**最低成本执行 = 每周一次跑 §4 的脚本 + 每两周读一次 changelog + GA 版本发布时执行同步决策流程。**

## 2. 监控清单（可手工逐条执行的 URL / 命令）

> 以下命令均验证于 2026-11-14。优先用 `gh api`（已登录，限额 5000/h）；无 gh 环境用 `curl`（匿名限额 60/h/IP，够单次周检用）。

### A. upstream preview 近期提交（每周）

```bash
# A1. 最近 30 条提交（看标题里的 feat/fix 与工单号）
gh api "repos/makeplane/plane/commits?sha=preview&per_page=30" \
  --jq '.[] | [.sha[0:7], .commit.committer.date[0:10],
        (.commit.message | split("\n")[0])] | @tsv'

# curl 版（无 gh 时）
curl -s "https://api.github.com/repos/makeplane/plane/commits?sha=preview&per_page=30" \
  | python3 -c "import json,sys; [print(c['sha'][:7], c['commit']['committer']['date'][:10], c['commit']['message'].splitlines()[0]) for c in json.load(sys.stdin)]"
```

判断规则：只关心 **feat: / fix(api|web): / release: / chore(release)** 与带 `WEB-`、`GIT-`、`INFRA-`、`SECUR-` 工单号的条目；纯 docs/deps 可忽略。

### B. 上游累积漂移与 release（每周）

```bash
# B1. 距离上一个 GA tag，preview 领先多少提交（观察下次 release 的体量）
gh api "repos/makeplane/plane/compare/v1.5.0-rc2...preview" \
  --jq '{ahead_by, total_commits, status}'
#   ahead_by 持续 >50 → 官方在攒 minor；<10 → 只有 hotfix 在路上

# B2. 最新 release 列表（rc/GA 判定）
gh api "repos/makeplane/plane/releases?per_page=5" \
  --jq '.[] | [.tag_name, .published_at, (.prerelease|tostring)] | @tsv'

# B3. 本 fork 与上游 preview 的漂移（fork 网络内 compare，不动本地 git）
gh api "repos/yuemingist/plane/compare/main...preview" \
  --jq '{ahead_by, behind_by, status}'
#   behind_by = 我们落后上游 preview 的提交数（含明哥自己的 main 领先量，需对照 B1 解读）
```

> 注意：upstream **没有 `main` 分支**（默认分支是 `preview`），不要用任务书里 `preview...main` 的方向；对 fork 用 `main...preview` 才是正确比较方向。

**GA 版本发布时（决策触发）**：按 [08.工作约定 §1](../../../项目管理/08.工作约定.md) 执行——提醒明哥 → 明哥拍板 → `git fetch upstream` → preview 快进 → `sync/YYYYMMDD` 分支 merge → `pnpm check` + 冒烟 → 回 main（要明哥点头）。**监控者只负责"提醒"，不执行合并。**

### C. changelog（每两周）

```bash
# C1. sitemap diff 法：保存上次快照，与本次对比（快照存 /tmp，不进仓库）
curl -s https://plane.so/changelog-sitemap.xml \
  | grep -o '<loc>[^<]*</loc>' | sed 's/<[^>]*>//g' | sort > /tmp/cl_now.txt
diff /tmp/cl_prev.txt /tmp/cl_now.txt   # 新增行 = 新 changelog 条目
cp /tmp/cl_now.txt /tmp/cl_prev.txt

# C2. 新条目详情：抓取新增 URL，重点读两处——
#     ① "What's new" 小节；② 是否出现 "Availability" 小节（2026-10 起的档位标注机制）
```

首轮没有 `cl_prev.txt` 时，以主文档 §3 时间线为基线（最后条目 2026-10-31）。

### D. 定价页（每月）

```bash
# D1. 提取正文文本后取 hash（页面含部署 ID 等噪音，不能 hash 原始 HTML）
curl -s https://plane.so/pricing \
  | python3 -c "
import sys, re, html
h = sys.stdin.read()
h = re.sub(r'<(script|style)[^>]*>.*?</\\1>', ' ', h, flags=re.S)
t = html.unescape(re.sub(r'<[^>]+>', '\n', h))
print('\n'.join(l.strip() for l in t.splitlines() if l.strip()))" \
  | shasum -a 256
# 与上次 hash 不同 → 人工 diff 正文，重点看：档位名、价格数字、每档功能清单、Self-hosted tab
```

基线 hash（2026-11-14）：见 §5 脚本首次运行的输出；此后记录在周报里滚动更新。

### E. SDK/组件包（每周）

```bash
npm view @makeplane/propel version time.modified
npm view @makeplane/plane-node-sdk version time.modified
npm view @makeplane/plane-mcp-server version time.modified
# 语义：propel 升 minor → CE 下个版本 UI 会动；
#      node-sdk 升版 → 云端 API 在扩（注意 CE 只有 v1，勿照抄 v2 文档：
#      https://developers.plane.so/api-reference/v2/introduction）；
#      mcp-server 持续 0.1.5 → 已停更 12 个月（截至 2026-11），继续观察是否复活
```

### F. 博客（每两周）

```bash
curl -s https://plane.so/blog-sitemap.xml \
  | grep -o '<loc>[^<]*</loc>' | sed 's/<[^>]*>//g' | grep '/blog/' | sort > /tmp/blog_now.txt
diff /tmp/blog_prev.txt /tmp/blog_now.txt
cp /tmp/blog_now.txt /tmp/blog_prev.txt
# 新增后人工读文章 JSON-LD datePublished；产品公告类（introducing-* / releasing-*）记入周报
```

### G. 论坛/状态页（每月人工）

- https://forum.plane.so/ —— 看置顶与热帖（官方社区论坛，2026-11 起监控方案纳入）。
- https://status.plane.so/ —— 云端事故；连续事故常伴随当周 release 加急。
- https://developers.plane.so/ —— 文档侧新增（API v2 端点扩充、self-hosting 指南）。

### H. 云端未落地功能复测（每月人工，需要测试账号）

- 登录云端 → 任一项目 → 设置 → 功能 → **里程碑**：开关还在？→ 开启后访问 `/milestones/`，仍是 404 则维持"未落地"结论（方法与基线截图见 [21.周期与里程碑/对比.md](../../21.周期与里程碑/对比.md)）。
- 顺带复测：Active Cycles 工作区页、Releases 入口是否出现。

## 4. 一键脚本（草案，已随本方案提交）

- 路径：[../../../运维/监控/plane_weekly_monitor.py](../../../运维/监控/plane_weekly_monitor.py)
- 用法：`python3 -I docs/运维/监控/plane_weekly_monitor.py --out /tmp/plane_monitor`
- 行为：抓取 §2 的 A/B/C/E/F 项（GitHub API + sitemap + npm + pricing hash），在输出目录写 `report-YYYY-MM-DD.md` 与各快照文件；**只写 --out 指定目录（默认 /tmp），绝不触碰仓库与 git**。
- 依赖：仅 Python 3 标准库；GitHub 匿名限额足够每周一次；如环境有 `GITHUB_TOKEN`，脚本会自动带上以提高限额。
- 约束：脚本为"草案"性质，首次接入真实流程时先人工核对一次输出再纳入周报。

## 5. 升级/停用规则

| 触发                                                                        | 动作                                                   |
| --------------------------------------------------------------------------- | ------------------------------------------------------ |
| release 出现 `v1.x.0` GA                                                    | 立即触发同步决策流程（§2.B），周报 §7 必填             |
| compare `ahead_by` 连续两周 >100                                            | 预告大版本，暂停 fork 内大面积 UI 重构（主文档趋势 7） |
| changelog 新条目出现 Availability=Enterprise Grid/Pro                       | 记入套餐矩阵观察，不进 M1                              |
| 云端 Milestones/Releases UI 落地                                            | 重新评估 21 号文档 D-05 结论，通知 R10 评分            |
| `developers.plane.so` 出现 v2 端点在 CE 落地（`api/v2` 出现在仓库 urls.py） | 更新主文档趋势 6，重估 API 集成策略                    |
| 官方连续 4 周无 release 且无 changelog                                      | 频率降为双周，周报合并                                 |
