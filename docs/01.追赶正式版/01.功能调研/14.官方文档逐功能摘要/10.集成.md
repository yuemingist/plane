# 10. 集成（Integrations）

> 抓取日期：2026-11-14｜来源：docs.plane.so/integrations/\*（11 页）｜对应 F-ID：待 R1 映射

## 定义

原生集成清单（integrations/about.md）：GitHub、GitHub Enterprise（Cloud ghe.com / Server 自托管）、GitLab（GitLab.com / Self-managed，界面名 Gitlab Enterprise）、Bitbucket（Cloud / Data Center）、Slack、Microsoft Teams（Enterprise Grid 且仅自托管）、Sentry、Draw.io、Claude（AI 编码代理）、Cursor（AI 编码代理）。自托管实例的各集成需实例管理员先做 OAuth 应用配置（developers.plane.so/self-hosting/govern/integrations/\*）。

## GitHub（Pro）

- 双向 issue 同步：GitHub issue 带 `plane` 标签→Plane 工作项；Plane 工作项带 `github` 标签→GitHub issue；同步标题/描述/状态/负责人/标签/评论/提及；互加跨链评论。
- 一个 GitHub org 只能连一个 Plane 工作区（冲突报错）；前提：工作区 Admin/Owner。
- 项目级 sync 映射：Plane 项目↔仓库；Issue Open/Closed→Plane 状态映射；方向单向（GitHub→Plane，**会覆盖 Plane 内容**）或双向。
- PR 状态自动化：PR 标题/描述中 `[WEB-344]`（带方括号）触发状态映射自动化；不带方括号仅链接；Draft Open/Open/Review Requested/Ready for Merge/Merged/Closed 六事件映射状态。
- 用户映射：连个人 GitHub 账号后评论以本人身份发出，否则显示集成机器人。
- Development 区块（分支/PR/commit）联动（Pro）。

## GitLab（Pro）

- 两种能力：issue 同步（`plane`/`gitlab` 标签触发；单向 GitLab→Plane 覆盖式或双向；评论通过专用线程往返；默认双向）+ MR 自动化。
- MR 引用：`[WEB-344]` 带方括号触发状态自动化（Draft open/Open/Review requested/Ready for merge/Merged/Closed）；关键词 closes/fixes 无效；只读 MR 标题与描述（分支名/commit 不读）。
- 防回退选项：阻止 MR 更新把工作项移回较早状态（按状态组再组内顺序比较）。
- 工作流拦截：MR 触发的状态变更被工作流禁止时，工作项不动，MR 上贴说明评论（解除后移除）。
- 同步细节：关闭状态→关闭 issue；移到 Completed 组关 issue、其他组（含 Cancelled）重开；删除不互删；标签在对面不存在则创建（小写）。

## Bitbucket（Pro）

- **仅 PR 自动化，不支持 issue 同步**；Cloud/Data Center；仓库连接自动建 webhook；PR 状态映射到项目状态；个人账号连接用于身份显示。

## Slack（Pro）

- Slack workspace OAuth 安装；个人账号连接用于 Thread Sync 显示本人名字。
- 消息快捷方式 Create a Work Item：选项目→Work Item 或 Intake→工作项类型（含必填自定义属性）→标题/描述（预填消息文本）→标签/状态/优先级/负责人→可选 Thread Sync 双向同步评论。
- `/plane` 命令快速创建；Link Work Item 快捷方式把已有工作项挂到线程；私有频道需手动把 Plane 应用加入频道。
- Plane 中状态/负责人等更新自动反映到 Slack 线程。

## Microsoft Teams（Enterprise Grid；仅自托管）

- 租户连接（工作区 Admin，可多租户）+个人账号连接两步。
- 能力：消息→建工作项或 Intake 请求（含类型与自定义属性）；Link Existing Work Item；线程-工作项双向同步（一线程一工作项）；链接预览卡（工作项/项目/周期/模块/页面）；卡上 Add me to Assignees；@Plane create / @Plane ask 命令（无命令默认 ask）；权限与 Plane 内一致。

## Sentry（Pro）

- OAuth 连接；状态映射（Unresolved/Resolved→Plane 状态）；Sentry Alert 动作自动建 Plane 工作项（可配优先级/负责人等）；Sentry issue 的 Issue Tracking→Makeplane 双向状态同步。

## Draw.io（Pro）

- 工作区 Admin 授权后，页面内可用 Draw.io 完整编辑器（diagram）与简化白板（board）块。

## Claude（Pro，AI 编码代理）

- 前提：装集成+工作区级 Anthropic API key（加密保存、校验后才存）+已连 GitHub（或 GHE）+至少一条项目↔仓库映射（可选分支）。
- 触发：把 Claude 加为工作项 assignee，或评论含 `@claude`；Claude 读工作项→克隆仓库→写代码→开 PR，进度回贴评论线程；回复同线程=续跑同一 session（无需再 @claude）；新顶层 @claude 评论=新 session。
- 模型下拉来自 Anthropic（≥2025-09 的模型），默认 Claude Sonnet 5；用量计入工作区 Anthropic key。
- 一项目可映射多仓库（使用时需指定）。

## Cursor（Pro，AI 编码代理）

- 同 Claude 模式：assignee 或 `@cursor` 触发；项目↔仓库映射（可多映射需指定）。
- 认证两模式：Shared key（工作区一个 Cursor API key，PR 由 bot 开）与 Per-user（各连各的 key，PR 以个人名义开、计入个人计划）；切 per-user 后未连接成员不可用，原工作区 key 转为管理员个人连接且保留可回切。

## 共性规则

- 集成入口均为 Workspace settings→Integrations；安装/配置需工作区 Admin。
- 自托管（商业版）需实例管理员预配置（GitHub App/GitLab App/Bitbucket OAuth/Slack/Sentry/DNS）。
- 个人账号连接失败时动作以集成 bot 身份显示。
