# 12. 自动化（Automations）、Plane Runner 与工作流（Workflows）

> 抓取日期：2026-11-14｜来源：docs.plane.so/automations/\*（3 页）、/workflows-and-approvals/workflows｜对应 F-ID：待 R1 映射

## Automations 总览（automations/overview.md）

两类：

- **默认自动化**（每项目内置，单一时间参数）：
  - Auto-archive closed work items：Completed/Cancelled 超过设定时长（1/3/6/9/12 月或自定义）自动归档；**活跃周期或模块中的项不会被归档**。
  - Auto-close work items：Backlog/Unstarted/Started 不活跃 N 时间→移到所选状态（如 Cancelled）。
  - Due date reminders（Business）：截止前 N 天给负责人+订阅者发应用内+邮件提醒；仅一项一窗口一次；必须有截止日期且有指派/订阅。
- **自定义自动化**（Business 起，见下）。

## Custom automations（automations/custom-automations.md，Business）

- 框架：Trigger（触发）→Conditions（条件，全部 AND 或 OR 组）→Actions（顺序执行）。
- 计划差异：
  - Business：项目内配置，作用于本项目；动作=Change property、Add comment。
  - Enterprise Grid（项目管理）：另有工作区级自动化（跨全部或所选项目）+Send webhook+Run script 动作+定时触发器。
  - Enterprise Grid+Workspace Governance：自动化收归工作区集中管理（一次性迁移，项目 Admin 失去项目内编辑权）。
- 触发器：Work item created/updated、State changed、Assignee changed、Comment added、Scheduled（Daily/Weekly/Monthly 1-31 号/五字段 Cron；时区默认项目→工作区→UTC）。
- 条件字段：State/Priority/Assignees/Labels/Work item type/Created by；算子 Is/Is not/In/Contains/比较四则。
- 动作：
  - Change property：Priority/State/Assignees/Labels（增删或全量替换）/起止日期/Cycle/Milestone（周期须同项目且未结束；里程碑须同项目且未归档；均为"移动"语义）。
  - Add comment：富文本+模板变量（如 {{priority}}）；以 Automation Bot 名义发内部评论。
  - Send webhook（EG）：URL 必须公网可达；secret key 保存时生成且仅明文显示一次（之后 plane*wh*••••XXXX 掩码）；自定义 header ≤20 个，可标记 secret 加密存储。
  - Run script（EG）：见 Runner。
- 管理：启用需至少 1 触发器+1 动作；草稿不运行；启用的不能删（先禁用）；Activity 看每次运行对象/成败/日志。

## Plane Runner（automations/plane-runner.md，Enterprise Grid）

- 沙箱化 JS/TS 执行引擎；构建块：**Scripts**（被触发）与 **Functions**（被脚本调用，带参数/返回类型，分类 HTTP/Notifications/Data/Utils/Custom）。
- 触发三类：
  - 事件自动化：入参 `input.event`（event_id/event_type/entity_type/entity_id/project_id/workspace_id/initiator_id/timestamp/payload.data/payload.previous_attributes）+variables。
  - 计划（cron）：仅 variables。
  - **工作流转换**：Pre-validation 脚本在转换前校验（`return {success:false}` 或 throw 阻断并向用户显示错误信息；链式按序全过才放行）；Post-action 转换后执行（失败不回滚仅记日志）。
- 脚本必须导出 `async function main(...)`；Variables 键值对参数化；SDK 通过 `Plane.` 全局；Functions 全局按需加载。
- 激活：工作区 Admin 授权（读写全部工作区资源+profile）。
- 测试、执行历史可查。

## Workflows and Approvals（workflows/workflows.md，Business 起）

- 定义允许的状态迁移、谁能执行、是否需审批。
- 计划差异：
  - Business：项目内一条 **default workflow**（管全部工作项）。
  - EG 项目管理：default+按类型的多条自定义 workflow+审批流+转换条件。
  - EG+治理：工作区统一目录（名称工作区唯一；恰一条 default 不可删；项目按 governance mode 消费）。
- 开启：项目设置 Workflows→Enable（默认 workflow 带 Default/Active 徽章）；列表可按状态/类型过滤、按名称/日期排序。
- 构建：Add states（含项目全部状态或挑选）；每状态 **Allow new work items** 开关（控制能否在该状态直接建项）；Add flow：
  - Transition flow：move to（目标状态）+by（默认 All 成员，可限成员列表）+with（条件）。
  - Approval flow（EG）：on approve move to / on reject move to / by / with；工作项停在待审批态，审批人在详情页看到 Approve/Reject 按钮。
- Transition conditions（EG）：Pre validation（Runner 脚本，全部通过才执行；失败向用户显示原因）+Post actions（转换后脚本）。
- 运行规则：只能在允许状态建项；非法迁移被拦截并提示（拖卡时卡片弹回）；类型匹配的自定义 workflow 优先于 default；停用暂停执行不丢配置。
- EG 治理模式（每类型一档）：Any（项目任选活跃工作流）/Constrained（限允许清单）/Required（全项目强制）；Any/Constrained 下可对单项目 **Pin**；切换 Required 覆盖全部 pin；effective workflow 解析顺序：Required→Pin→项目自选→工作区 default；切换 workflow 时不在新工作流内的状态上的工作项移到 fallback 状态（有预览）。
- 其他：查看更改历史；删除自定义 workflow 后其工作项回落 default。
