## 1. 目标与云端形态

- **搜索筛选行**：搜索条下「Projects is --」条件 chip（is 运算符+项目多选+清除按钮+「已应用所有筛选」toast）——高级过滤（32 号 D-06）。
- **命令面板升级**：云端搜索弹窗=纯搜索（chips+计数+「Go to advanced search page」入口+右上筛选图标）；**CE 命令面板全量命令清单是反超项**（32 号 D-01：不做减法）——CE 追加「进入高级搜索页」入口与实体 chips，保留命令面板。
- **设置侧边栏「搜索设置」框**（32 号 D-04/UX-10；20 号 P0-8 ④已列入快赢包——本条与其衔接）。
- **CJK 检索质量**：云端「调研」单查 0 结果（分词边界 bug）；「webhook」「自动化」正常——CE 追赶时选型/验证搜索后端 CJK 行为（65 号 D-14）。
- 深测文档：`docs/01.追赶正式版/01.功能调研/32.全局搜索与命令面板/对比.md`、`65.通知内容与导出搜索/对比.md`（§1.7）。

- **后端搜索 API 全在（★★）**：`apps/api/plane/app/urls/search.py` 三条路由全注册——`workspaces/<slug>/search/`（GlobalSearchEndpoint）、`workspaces/<slug>/projects/<id>/search-issues/`（IssueSearchEndpoint）、`workspaces/<slug>/entity-search/`（SearchEndpoint）。前端调用点：`apps/web/services/workspace.service.ts:216`（`/search/`，命令面板消费）——entity-search 端点前端无消费。
- **命令面板反超资产**：CE 全量命令+序列键+「工作区级别」跨工作区开关（32 号 D-05：CE 保留多工作区搜索，不删）。

## 3. 后端改动面

1. **GlobalSearchEndpoint 实体覆盖核对与扩展**：逐实体验证（project/issue/cycle/module/view/page/comment/teamspace——teamspace CE 无实体，chip 对应「全部工作区内容」或隐藏）；不足处补 queryset 分支；返回结构统一为 chips 计数+结果列表形状。
2. **entity-search 端点增强**（可选）：为高级搜索页筛选行（Projects is 条件）提供服务端过滤参数（project 过滤大概率已在——SearchEndpoint 现状参数核对）。
3. **CJK 检索验证与优化**：现搜索实现（likely Postgres icontains/search_vector）对 2 字 CJK 查询的行为验证；如需分词，评估 pg_trgm/简单 n-gram 兜底（**不引入 OpenSearch**——Enhanced Search 是 P2 范畴；确保「调研」类 ≥2 字 CJK 可命中——云端反而在这是 0 结果，CE 目标=不劣于云端）。
4. 无新表无迁移（纯查询面）。

## 4. 前端改动面（apps/web）

## 9. 风险与未知

1. **GlobalSearchEndpoint 各实体覆盖面未逐个验证**（本 brief 代码核对项）——页面/评论/团队空间 chips 的结果来源可能需后端补齐；团队空间（Teamspaces）CE 无实体，chips 处理为隐藏或映射「全部」。

3. 排序：云端结果页无显式排序控件（65 号 §1.7）——CE 按相关性（后端默认序）实现，不加排序 UI。
4. 搜索结果分页形态未实测（结果列表分页控件）——按 CE 列表通用分页。
5. 与 P2-8（Work item security audience 可见性）联动：搜索结果过滤需纳入未来 audience 面（本期按成员可见性）。
