## 1. 目标与云端形态

项目自动化页第 3 条内置规则（58 号 D-08/§3.4 实测）：

- 自动化页新增「自动提醒」开关行，文案：「在工作项到期前，通过电子邮件和应用内通知提醒受理人。」
- 翻开后展开「**提前提醒**」下拉：**1 天/2 天/…/7 天枚举（仅天数一个参数，默认 1 天）**；无自定义时刻、无提醒对象选择。
- 行为：到期（due_date）前 N 天，向**受理人**发邮件+应用内通知；提醒对象=assignee（文案口径），含已完成/已关闭工作项的排除语义（未实测，按「仅未完成」设计，见 §9）。
- 深测文档：`docs/01.追赶正式版/01.功能调研/58.自动化与工作流深测/对比.md`（§3.4 步骤表+截图 cloud-auto-reminder-days-options-2026-11-14.png）。

## 3. 后端改动面

1. **配置存储（1 字段迁移）**：`Project.reminder_days_before_due`（IntegerField，0=关/1-7；或存 `Project.config` 类 JSON——为对齐云端「开关+1-7 枚举默认 1」语义用整型字段最简，choices 在 serializer 层）。走 `project.py` 既有字段区追加+1 个迁移。
2. **每日扫描任务**：`bgtasks/issue_automation_task.py` 追加 `send_due_work_item_reminders()`（或独立 `reminder_task.py`）：查询 `due_date = today + N 天 AND 未完成（state.group not in completed/cancelled）AND assignee 非空 AND project.reminder_days_before_due > 0`，按项目批量处理。
3. **通知生成**：对每个受理人生成 Notification（sender 标记 `auto-reminder`，data 带 work_item id 与 due_date；triggered_by 可为 None/系统）——与 notification_task 的防重复机制对齐：**同工作项同日去重**（可查当日 EmailNotificationLog 或 Notification 已存在记录），避免 beat 重跑重复提醒。
4. **邮件发送**：新增模板 `apps/api/templates/emails/work_item_due_reminder.html`；走 `email_notification_task.send_email_notification` 通道（ENABLE_SMTP 关时仅入栈不发，对齐现状行为）；邮件文案含工作项标题/序列号/到期日/链接。
5. **API**：`ProjectRetrieveUpdateViewSet` 暴露新字段（serializer+项目设置权限沿用）；无需新端点。
6. 应用内通知的 receiver 偏好：尊重 UserNotificationPreference（提醒属「属性变更/状态变更」之外的独立类——云端偏好矩阵无此开关（65 号 4.1 与 CE 逐字一致、均 5 组），故提醒通知不受偏好抑制或归入默认发送；按云端口径=直接发送，不新增偏好键）。

- 后端 pytest：扫描任务（构造 due_date=today+N、跨项目、无受理人排除、已完成排除）、去重（同日重跑不重复）、N=1..7 边界、N=0 不提醒、Notification+EmailNotificationLog 写入、ENABLE_SMTP=0 时仅记日志。

## 6. 依赖与并行性

- **前置**：无硬依赖（通知/邮件基建全在）。自托管需开 SMTP 才有邮件效果——部署文档说明即可。
- **可并行**：与 P1-1 完全独立可并行；与 P1-10 共享 beat 模式但无代码耦合。
- **被依赖**：P1-1 规则引擎一期不依赖本条（20 号路线图曾提「P1-1 是 P1-2 引擎的邮件/调度基建前置」——本 brief 校正：提醒是独立 beat 任务，非引擎前置；引擎若要支持提醒类 handler 可后续复用本条扫描管道）。

## 9. 风险与未知

1. **已完成排除语义未实测**（58 号待验证 6：试用工作区未构造到期场景，实际邮件未验证）——按「state group ≠ completed/cancelled」设计，待云端复核。
2. 提醒时刻（当天几点发）未实测：beat 每日一跑取项目时区还是 UTC 需定夺（CE celery.py 时区配置沿用现状）。
3. 偏好抑制口径：云端偏好矩阵（65 号 4.1）无提醒开关，追赶按「不新增偏好、直接发送」；若官方后续加偏好键需回补。
4. 大批量性能：到期工作项多时批量发送走 Celery 分片，不做同步循环。
5. 重复提醒策略（每到期只提醒一次 vs 每天提醒直至到期）云端未实测——按一次提醒设计，留重提醒扩展。
