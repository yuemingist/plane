## 1. 目标与云端形态

把工作项通知链路从「结构同源但缺口」补到云端体验（65 号实测）：

- **收件箱头部**：返回/全部标记为已读/刷新 + **「选择默认视图」下拉**（CE 缺，65 号 D-02）。
- **列表工具行**：搜索/**收件箱筛选**/排序方式（CE 仅有筛选/显示，缺搜索与排序——65 号 D-03；31 号 D-01/D-02 同记）。
- **单条操作**：标记已读/未读/**Archive/暂停（snooze）**——CE 后端字段与操作 API 已在（snoozed_till/archived_at），UI 组件同源但**未联调验证**（65 号 D-04）。
- **通知偏好**：邮件通知 5 组开关矩阵（属性变更/状态变更[子项 工作项完成]/评论/提及+总开关）**与云端逐字一致**（65 号 1.3/4.1：无需追赶，仅回归确认）。
- **自我触发抑制**：triggered_by==receiver 不产生通知（65 号 1.2 实测：自我指派/自我提及均 0 通知）——CE 代码已排除 actor（见 §2），需**双账号实测闭环**（65 号遗留 2）。
- **提及 tab 空态文案**：云端「您的工作项的提及将显示在此处」vs CE「您订阅的工作项的更新将显示在此处」（65 号 D-05 文案微差）。
- **通知内容联动**：自动化通知渲染（「Automation added assignee…」形态已在云端观测）——CE 自动化落地（P1-1）后 Bot 通知复用同链路。
- 深测文档：`docs/01.追赶正式版/01.功能调研/65.通知内容与导出搜索/对比.md`、`31.通知与收件箱/对比.md`。

## 3. 后端改动面（少）

1. **通知搜索**：`notification/base.py` 列表端点加 `search` 查询参数（对 Notification.data/触发标题/项目名 icontains——data 为 JSON，需在写入时冗余 `entity_title` 类可检索字段或用 JSONB contains；**建议 1 小迁移**给 Notification 加 `entity_title` CharField 冗余+回填 data 迁移）。
2. **排序**：确认现有 ordering 参数暴露（created_at/read_at）+默认视图筛选参数（unread/snoozed/archived 组合——现有多为前端过滤，后端补参数化）。
3. **回归确认项**（不开发）：偏好矩阵字段与云端一致（已在）；snooze/archive 端点（已在）。
4. **自动化 Bot 通知**：依赖 P1-1 的 bot_user 活动流——通知创建管道无需改（triggered_by=bot）。

## 4. 前端改动面

1. 头部「选择默认视图」下拉（全部/未读/已归档/已暂停分组——选项集 65 号待验证 4 未展开，按过滤器组合实现）+默认视图持久化（localStorage 或用户属性）。
2. 工具行加「搜索」图标（列表内搜索框→调后端 search 参数）+「排序方式」（时间/未读优先）。
3. 单条操作菜单联调验证+补缺（标记已读/未读/Archive/暂停四个 action 的 API 接线确认——组件存在但需验证与 `base.py:158/:170` 端点参数匹配）。
4. 提及 tab 空态文案统一（empty-state locale 键替换）。
5. i18n：新增键少量；提及 tab 空态文案替换。

## 9. 风险与未知

1. **「选择默认视图」「排序方式」弹层选项集未展开**（65 号待验证 4）——按合理集合实现，云端复核微调。

3. 邮件正文形态未覆盖（65 号遗留 1：163 邮箱登录未成功，正文含订阅取消链接/回复直达的形态空白）——CE 邮件模板按现有 stack 聚合机制渲染，正文样式对齐 CE 既有邮件体系（不强仿云端）。
4. 通知偏好入口在云端位于用户菜单（31 号 D-04：云端入口未实测展开）——CE 入口现状（个人资料设置）保留。
