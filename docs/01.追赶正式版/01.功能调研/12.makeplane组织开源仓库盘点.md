## 3. 重点仓库深查

### 3.1 plane-mcp-server（MIT，v0.3.5，2026-11-11 活跃）

**定位**：官方 Model Context Protocol server，给 AI agent 暴露 Plane 全部读写能力。FastMCP 3.2.0 + 官方 `plane-sdk==0.3.1`（即 plane-python-sdk）构建。

**工具面（代码证据：`plane_mcp/tools/README.md`、`plane_mcp/tools/`）**：

- **30 个工具、207 个 action**（从 177 个细粒度工具合并而来，169 个旧名仍可解析）
- 工具清单（按资源）：`workitem`（12 actions，含 `search`/`count`/`archive`/`retrieve_by_identifier`）、`cycle`（11，含 transfer/complete/archive）、`module`（10）、`page`（11，含 `set_collection`/`attach_to_workitem`）、`collection`（13，Wiki Collections 的成员/页面管理）、`customer`（7，含 `list_workitems`/`manage_workitems`）、`customer_property`（7）、`customer_request`（5）、`initiative`（10）、`intake`（5）、`milestone`（7）、`release`（9，含 **`get_changelog`/`update_changelog`**）、`release_label`（6）、`release_tag`（5）、`work_log`（4）、`project_estimate`（8）、`workitem_property`（14，自定义属性+option 管理）、`workitem_type`（7，含 `import_to_project`）、`workitem_relation`（7）、`workitem_link`（5）、`workitem_comment`（5）、`workitem_attachment`（5，含 `upload_from_url`，带 SSRF guard）、`workitem_activity`（2）、`label`/`state`/`template`/`member`（5，含 `list_roles`/`retrieve_role`）/`project`（11，含 `get_features`/`update_features`/`worklog_summary`）/`workspace`（3，含 **`get_features`/`update_features`**）/`get_pql_reference`
- **PQL（Plane Query Language）**：`pql_reference.py` 定义了完整查询语法（`priority = "urgent" AND assignee = currentUser()`、`stateGroup IN openStates() AND isOverdue()`、自定义属性 `cf["<uuid>"]`、`activeCycle()` 等），5 个 list 工具支持 `pql` 参数。Enterprise-grid 页面确认 PQL 是官方宣传的跨组织查询能力

**连接性与 CE 兼容性（代码证据：`plane_mcp/client.py`、`auth/plane_oauth_provider.py`）**：

- `PLANE_BASE_URL` 可指向任意自托管实例（默认 `https://api.plane.so`），另有 `PLANE_INTERNAL_BASE_URL` 供服务端部署；**因此理论上可连 CE 自托管**，但：
  - CE 的公开 API 仅 `api/v1`（本仓库 `apps/api/plane/urls.py`：`path("api/v1/", include("plane.api.urls"))`），且资源只覆盖：`asset, cycle, intake, invite, label, member, module, project, state, user, work_item, sticky`（`plane/api/urls/__init__.py`）+ estimate 视图
  - **CE 没有 `/api/v2`**（最新 preview 分支核实），也没有 `/auth/o/` OAuth provider 端点
  - 结论：接 CE 时 **v1 资源类工具可用**（workitem/cycle/module/state/label/intake/project/member 等），**v2/EE 类工具（customer/initiative/release/milestone/page/collection/work_log/workitem_property/workitem_type/PQL/features）不可用**（404 或 402）
- **计划门控是服务端行为**：`toolkit/governance.py` 的 `plan_gated()` 捕获 API 返回的 **402** 状态码，仅 4 处标注：`work_log`（Time tracking）、`workitem_type`、`workitem_property`、project features——反映这些在云端是 Pro 起的付费开关
- 托管部署形态：`https://mcp.plane.so/http/mcp`（OAuth）与 `/http/api-key/mcp`（PAT），SSE 端点已弃用保留兼容；EE chart 也支持把 MCP server 作为组件自部署（`mcp_server.path_prefix: '/mcp'`）

**完成度**：高。带 conformance/dispatch/pagination/governance/vocabulary 等完整测试套件（`tests/`，`SpyClient` 对齐真实 SDK 签名）、输出 schema 裁剪、legacy 别名表、工具顺序 wire-format 保证。工程化程度远超一般社区 MCP。

### 3.2 plane-python-sdk v0.3.3 / plane-node-sdk v0.3.2（均 MIT，活跃）

**双 API 面**：`plane/config.py`——`base_path` 追加 `/api/v1`，同时保留 `api_root` 供 v2 资源自建 `/api/v2` 前缀。

**v1 面**（CE 大部分可用）：work_items（含 comments/attachments/links/relations/dependencies/activities/pages/work_logs/custom_relations）、projects、cycles、modules、states、labels、estimates、intake、stickies、members、users、invites、templates、teamspaces、workflows、workspace_templates、customers、initiatives、releases、agent_runs 等——注意后半部分实际走 v2 数据模型。

**v2 面**（`plane/api/v2/`，**407 个 operation**，来自 `_generated/constants.py`）：这是最有价值的"正式版 API 地图"：

- 常量文件头注释直接写着生成来源：**`Source: ../plane-ee/apps/api/plane/api_v2/core/schema/openapi`** —— 即 EE 代码位于私有仓库 **`plane-ee`**，其 v2 API 是独立 Django app（`plane/api_v2/`）
- v2 资源全清单（407 ops 分布于）：work_items、attachments、assets、comments、activities、cycles、modules、pages、labels、states、estimates、milestones、intakes、initiatives、releases、customers、customer_properties、collections（含 `collections_members`/`collections_pages_search`）、stickies、teamspaces、worklogs、webhooks、webhook_logs、invitations、members、roles、users、workspaces、**audit_logs**、**features**、**permissions**、**permission_schemes**、**views**、**wiki_node**、**workflows**、**automations**（activities/edges/nodes——图结构自动化）、**group_sync**（IdP 组→角色/项目映射：config/project_mappings/workspace_mappings，即 SCIM 组同步）、**artifacts**（"Plane Intelligence generate/publish/host flow"）
- **功能开关模型**（`models/v2/features.py`）反推 EE 功能矩阵：
  - Workspace 级 toggle：`is_customer_enabled`、`is_initiative_enabled`、`is_member_project_creation_enabled`、`is_pi_enabled`（Plane Intelligence）、`is_project_grouping_enabled`、`is_release_enabled`、`is_state_duration_enabled`、`is_teams_enabled`（Teamspaces）、`is_wiki_enabled`、`is_work_item_types_enabled`、`is_workitem_hierarchy_enabled`（端点 `GET/PATCH /workspaces/{slug}/features/`）
  - Project 级 toggle：`is_automated_cycle_enabled`、`is_epic_enabled`、`is_manually_start_end_cycles_enabled`、`is_milestone_enabled`、`is_parallel_cycles_enabled`、`is_project_updates_enabled`、`is_workflow_enabled`
- **Agent Runs 模型**（`models/agent_runs.py`）：status（created/in_progress/awaiting/completed/stopping/stopped/failed/stale）、type=comment_thread、activity 类型 action/elicitation/error/prompt/response/thought、signal auth_request/continue/select/stop——Plane Agents 平台的运行时协议
- OAuth（node SDK `src/client/oauth-client.ts`）：`{base}/auth/o/authorize-app/`、`{base}/auth/o/token/`（Django oauth2_provider 风格）——**CE 无此端点**，属 EE/云端能力

从所有公开仓库引用的端点/配置/模型反推云端与 EE 的能力面：

**A. EE 私有仓库结构**：`plane-ee/apps/api/plane/api_v2/core/schema/openapi`（plane-python-sdk 生成常量的来源注释）→ EE 是与 CE 平行的完整代码库（同构 Django 工程 + 独立 `api_v2` app）。

**B. 正式版独有 API 面（v2，407 ops）**：customers、initiatives、releases、milestones、collections（Wiki Collections）、wiki、views（含 workspace views）、audit logs、features、roles/permissions/permission_schemes、group_sync（SCIM 组同步）、automations（图结构 trigger/action）、agent_runs、artifacts（AI 生成/发布/托管）、worklogs、webhook_logs、stickies、teamspaces。

**C. 特殊云端端点**：

- `api.plane.so`：默认 API；OAuth 端点 `/auth/o/authorize-app/`、`/auth/o/token/`（CE 无）
- `mcp.plane.so`：托管 MCP（OAuth + PAT 两种）
- `prime.plane.so`：**许可服务器**（EE chart 必配）
- `prime-cli.plane.so`：闭源 CLI 安装器
- `artifacts.plane.so`：官方镜像仓库（CE 镜像也在此）
- `app.plane.so`：云端主应用

**D. 架构级能力（EE chart 组件反推）**：自托管 AI（pi-\*，BYO 模型含 Bedrock/自定义 LLM/embedding）、自动化执行引擎（node-runner + automation/webhook/agent/outbox 消费器）、PII/敏感数据扫描（argus）、增强搜索（OpenSearch + search-index job）、独立 external-api 层、独立 email 服务、docs 站点服务、drawio/iframely 嵌套服务、live 指标导出（live-exporter）、silence 对象存储（pgsty/silo）。

**E. Feature flag 体系**：workspace/project 两级 feature toggle API（`/features/`），把 customers/initiatives/releases/wiki/teamspaces/PI/work-item-types/workitem-hierarchy/state-duration/project-grouping/automated-cycle/parallel-cycles/milestone/epic/workflow/update 做成可开关——正式版用统一 feature flag 而非编译期区分。

**F. 企业治理**：RBAC+GAC 双层角色（pricing 数据）、Power K（键盘优先全局入口）、LDAP、Group Sync、工作项级安全（work item security）、Custom SLA、Databases（Enterprise 独有新功能）、配置版本控制（enterprise-grid 页面："Version control for configuration"）、Plane Runner 自动化。

## 6. U12 复核结论（2026-11-14，plane.so/pricing 原始 HTML 解析）

**结论：10 号文档记录的「Pro 套餐 SAML 行 cloud=No, self-hosted=Yes」异常表述属实，且仍然存在，但现在可以给出更精确的解释——这是官方故意的差异化定价，不是错误。**

页面内嵌 JSON（RSC payload）中的完整定义（两处一致）：

```json
{
  "name": "SAML",
  "description": "Get the officially supported SAML implementation and make Plane secure with any IdP.",
  "values": { "Free": "unavailable", "Pro": "unavailable", "Business": "available", "Enterprise": "available" },
  "valuesByTab": {
    "cloud": { "Free": "unavailable", "Pro": "unavailable", "Business": "available", "Enterprise": "available" },
    "self-hosted": { "Free": "unavailable", "Pro": "available", "Business": "available", "Enterprise": "available" }
  }
}
```

- **SAML 与 OIDC 是全部 87 个 feature 行中仅有的 2 个 cloud/self-hosted 取值不同的行**：云端需 Business（$13/席/月）起，自托管 Pro（$6/席/月）即可用。LDAP/Group Sync 仍为 Enterprise Grid 专属。

> 【勘误 2026-11-14】原结论「全部 87 个 feature 行」；修正为「**88 行**」——2026-11-14 重新抓取解析为 88 行（多出 Workspace Members Import 等，官方页面微调 +1 行，13 号冲突表 C-06）；本节其余结论（SAML/OIDC 为仅有的两行 cloud/self-hosted 取值不同、pricing 页整体改版）维持成立；依据：13.正式版功能基线.md §2.2 P-Row 索引/§6。

- **完整套餐矩阵已整体改版**（与 10 号文档记录的旧版不同）：
  - **Free $0**：12 users 席位上限、基础 RBAC、Intake In-app、Power K
