# 通知与收件箱 对比（实测日期 2026-11-14）

> 环境：云端 app.plane.so（yueming 工作区）；CE `http://yuemingmac-mini.tail43aa97.ts.net:3000`（demo-workspace）。

## 页面结构对比（云端 vs CE）

### 工作区收件箱（通知中心）

| 结构     | 云端 `/yueming/notifications/`                                   | CE `/demo-workspace/notifications/`                  |
| -------- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| 入口     | 顶栏邮件图标（收件箱按钮）                                       | 顶栏邮件图标 + 侧边栏"收件箱"链接                    |
| 头部操作 | 返回、收件箱标题、全部标记为已读、刷新、**选择默认视图**（下拉） | 返回、收件箱、全部标记为已读、刷新（无默认视图选择） |
| Tab      | 全部 / 提及                                                      | 全部 / 提及（一致）                                  |
| 工具     | 搜索、收件箱筛选、排序方式                                       | 收件箱筛选、显示（**无搜索框**，"显示"≈排序/分组）   |
| 空态     | "您订阅的工作项的更新将显示在此处" + 右侧"未选择通知"插画        | 完全一致的文案与插画                                 |
| 详情面板 | 选择一条通知以查看其详细信息                                     | 选择一条通知以查看详情                               |

> 两者通知列表本次均为空（云端 business trial 无活动通知；CE demo-workspace 无订阅通知）。通知卡片/联动细节（评论通知、提及通知的实际渲染）未能实测到内容形态。

### 通知偏好设置

| 结构         | 云端                                                               | CE                                                                                            |
| ------------ | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 入口         | 用户菜单（自动化无法展开，见限制说明）；工作区设置侧边栏中无通知项 | `/settings/profile/notifications`（个人资料侧边栏：个人资料/偏好设置/通知/安全/个人访问令牌） |
| 邮件通知开关 | 未能实测（入口受限）                                               | **有**：属性变更、状态变更（含子项"工作项完成"）、评论、提及，共 5 组 toggle，默认全开        |
| Webhook      | 工作区设置有独立 Webhooks 页                                       | 工作区设置有独立 Webhooks 页（一致）                                                          |
| Push         | 未见                                                               | 未见                                                                                          |

### 项目 Intake（CE 的 Inbox 分诊）

| 结构       | 云端 GZRC Intake                           | CE WEB Intake                                                                                              |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 顶部       | **Intake source** 按钮 + Add work item + … | 添加工作项（**无 Intake source 配置按钮**）                                                                |
| Tab        | 未处理 N / 已处理                          | 未处理 1 / 已处理（一致）                                                                                  |
| 筛选排序   | Filters、创建时间                          | Filters、创建时间（一致；CE 文案为英文 Filters）                                                           |
| 列表筛选条 | Status 待处理 chip                         | Status 待处理 chip（一致）                                                                                 |
| 详情       | —（云端无待处理项）                        | WEB-13 待处理徽标、**接受/拒绝按钮**、State=Triage（disabled）、Properties、附件、活动流（全部/活动/评论） |

> CE Intake 分诊链路完整：pending 项在主列表不可见（Triage 状态），接受后进入 Todo。

## 待验证问题闭环

- **评论通知联动**：两边通知列表均无实际通知内容可观察（云端 trial 无活动、CE 无订阅数据）。CE 有 5 组邮件通知开关证明通知偏好链路存在；评论 → 通知的端到端渲染本次无法闭环，列为未覆盖。
- **CE 数据 1 条 intake pending 实测**：确认 WEB-13 处于"未处理"Tab、Triage 状态、主 issue 列表不可见，详情页提供接受/拒绝操作，符合"CE 的 Inbox 即 intake 分诊"的预期。
- **自动化限制说明**：云端与 CE 的顶栏"用户菜单"下拉均无法通过合成点击展开（点击无效果或开合抵消），云端通知偏好页因此未能实测；CE 通过直达 URL `/settings/profile/notifications` 完成。
