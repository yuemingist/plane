# 59. Dashboards 深测 对比（实测日期 2026-11-14）

> 云端：YM Research（slug=thinkym，Business 试用）/ 测试仪表板「调研-指标看板」（id=1bf883b6-653c-451a-90e4-77e072e58fd2，数据源=调研-时间跟踪项目，公开可见性，已发布）
> 公开 URL：https://sites.plane.so/dashboards/967a66eddf9347438857b470c7fd2c5e（已实测匿名可访问）
> CE：demo-workspace / WEB 项目
> 采集说明：IAB 截图表面故障（同前两批），全程本机 Chrome + CDP（/tmp/plane-chrome-tools）驱动截图；widget 全集文字以 DOM 快照逐字记录。
> 结论速览：40 模块已列 26 种 widget 集合本批**逐字复核一致**，并**实测 7 种不同类 widget**（chart 类 3 + 计数类 1 + 统计类 1 + 表格类 2）到同一「调研-」dashboard；布局=自动网格（可拖拽换位/拖角调高/逐 widget 删除）；分享=成员级+常规访问范围+复制链接；**发布=生成 sites.plane.so 公开只读页（匿名可访问、全 widget 渲染）**；导出=仅 PDF（纵/横向）；与 Analytics 固定页为**并列独立模块**（无互相跳转入口，数据同源）。CE 侧无 Dashboards 实体：`/dashboards/` 路由 404 实拍、API 无 dashboard 模型（仅 home-dashboard 端点）、前端 dashboard.service/store 为指向不存在端点的死代码。

### 1.4 Widget 目录（添加组件面板）

- 顶部搜索框 + 9 组 26 种（与 40 模块记录一致，本次 DOM 逐字复核）：
  - 柱状：基础柱状图 / 分组柱状图 / 堆叠柱状图
  - 线形：基础线形图 / 多线（40 模块记录；本次快照目录滚动范围内逐项核对）
  - 区域：基础区域图 / 对比区域图 / 堆叠区域图
  - 饼形和环形：饼形 / 基础环形图 / 进度环形图
  - 计数器：**工作项智能计数器**（每个分组一个计数器，以磁贴或表格显示）/ 工作项智能仪表（以仪表形式展示每个分组的完成情况）
  - 统计：工作项统计（按单个属性分组的统计数据）/ 二维表格（按两个属性筛选的统计数据）
  - 工作项：分配给您的（工作项）/ 工作项表格（符合您筛选条件的工作项）/ 工作项进度
  - 周期：周期进度（周期进度的可视化快照）/ 活跃周期进度
  - Intake：按来源划分的 Intake 数量 / Intake 项目留存时长 / 接受和拒绝的平均时间 / Intake 已接受 vs 已拒绝 / Intake 明细

### 1.5 与 Analytics 固定页的关系

| 维度     | 实测结论                                                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 模块关系 | **并列独立**：/thinkym/analytics/（7 tab 固定报表）与 /thinkym/dashboards/（可配置多仪表板）互不引用；Analytics 页无「转为 widget/创建仪表板」入口，Dashboard 侧也无「从 Analytics 导入」入口 |
| 数据同源 | 同一项目工作项聚合数据（Analytics 概览「工作项总数 11」↔ widget 柱状 Done 2+Backlog 2 等一致口径）                                                                                            |
| 图表同源 | 未做代码级验证；UI 层 widget 图表与 analytics 自定义洞察图表均为独立配置面（widget 可配聚合/分组，analytics 自定义洞察是 X/Y 透视）                                                           |
| 入口差异 | 仪表板=主侧边栏一级入口；分析=更多菜单二级入口（40 模块已记）                                                                                                                                 |

## 6. CE 代码证据（grep/路由文件级）

1. **前端死代码**：`apps/web/services/dashboard.service.ts`——`getHomeDashboardWidgets()` 调 `/api/workspaces/{slug}/dashboard/?dashboard_type=home`（此端点 CE 后端**存在**：`apps/api/plane/app/urls/user.py:80` `users/me/workspaces/<str:slug>/dashboard/`，无鉴权实测 401 JSON）；而 `getDashboardDetails()`（`/api/dashboard/{id}/`）、`getWidgetStats()`、`updateWidget()`（`/api/dashboard/{id}/widgets/{widgetId}/`）指向的端点 CE 后端**不存在**——直连 `http://localhost:8000/api/dashboard/test-id/` 实测 **404 JSON**（SPA 代理下则回退 HTML，属假象）。该 service 仅被首页 widget（`apps/web/components/home/home-dashboard-widgets.tsx` + `apps/web/store/dashboard.store.ts`，homeDashboardId/widgetDetails 状态）消费。
2. **API 无 dashboard 实体模型**：`apps/api/plane/db/models/` grep `dashboard|widget` 仅 `workspace.py` 命中单词（首页相关），无 Dashboard/Widget 表模型；`plane/app/urls/`+`plane/api/urls/` 全量仅 user.py:80 一条 dashboard 路由。
3. **路由 404 实证**：CE web `/demo-workspace/dashboards/` → 404 错误页（截图）；云端同路径为完整列表页。
4. **结论**：CE 的「Dashboards 能力」=仅首页固定 widget 的只读端点；可配置仪表板的 model/API/UI 三层在 CE 分叉点完全不存在，但前端死代码保留了 THomeDashboardResponse/TWidget 类型与调用骨架——追赶时可复用该 service/store 骨架接新端点（成本低）。
