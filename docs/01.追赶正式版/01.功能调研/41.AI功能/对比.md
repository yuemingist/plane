### 云端 AI 聊天工作台（/ai-chat/）

- 会话管理：开始新对话、搜索、最近 threads（当前无会话，"No threads available"）。
- 二级导航：**技能**（/ai-skills）、**用量**（/ai-usage）、**分析**（/ai-analytics）、**记忆**（/ai-memory）。
- 输入区：附件上传、"Build" 模式开关（Talk to build：AI 可动手创建/修改工作项等）、Enable web search、模型选择（Claude Sonnet 5.5）、语音录音。
- 空态建议（Suggestions）："Create a Sticky with details of all Urgent work items…"、"Create a Page in the Wiki with work logs for each member…"——都是"动手做"类，不是纯问答。
- 免责声明："Plane AI can make mistakes, please double-check responses."

### 云端 AI 技能页（/ai-skills，标「测试版」badge）

- 工作区级别 / 个人 两个 tab；「添加工作区技能」自定义技能。
- 12 个系统技能：/my-work、/standup、/project-status、/cycle-report、/team-workload、/blocked-items、/needs-attention、/recent-activity、/find-pages、/time-tracking、/file-bug（Build mode）、/new-prd（Build mode）。

### 云端上下文 AI 面板（顶栏 AI assistant，工作项详情页打开）

- 自动挂载上下文：当前工作项 chip（GZRC-2）+ 当前项目 chip（GZRC）。
- 情境建议：①"Add a comment summarizing all the activity/comments pertaining to the work item"（= **AI summary**）②"Update the description of this work item" ③"Create sub-tasks for this work item"。
- 输入框仍带 Build/模型选择/录音。AI summary 的入口即此建议项（点击后 AI 生成并回帖），工作项 "…" 菜单内**没有**独立 AI 菜单项。

### 云端 AI 筛选 / PQL（工作项列表筛选下拉）

- 筛选下拉最顶部两项：**AI filters** 与 **PQL**（其后才是 Title/Text/Type/…/State/Cycle/Module 等常规筛选）。
- 点 AI filters 后出现筛选条：自然语言输入（"Describe your filter in plain language..."）+ Basic/PQL 两个 tab + PQL 查询框 + Run 按钮 + 另存为。
- 实测：输入 "priority is high" 回车 → 自动转成 PQL `priority = "high"` 并应用筛选（GZRC 无 high 项故列表为空，机制生效）；可「清除全部」「另存为」。
- 同一套 Basic/PQL 自然语言筛选也内嵌在 Dashboard 创建弹窗与 widget 筛选中（见 40 模块文档）。

### 云端 Intake AI（auto-triage）

- Intake 页（未处理/已处理 tab）与 intake 工作项详情（接受/拒绝/暂停/标记为重复）**均未发现 AI 自动分类按钮**——当前账号/套餐下该能力未见 UI 入口（可能仅对开启 Intake AI 的套餐/灰度可见）。已记为待确认。

### CE 基线（无任何 AI 入口）

- 最左导航只有 Work/Wiki/设置，无 AI 项；顶栏只有 收件箱/帮助/GitHub 加星/用户菜单，无 AI assistant。
- 无 /ai-chat 路由；筛选下拉无 AI filters/PQL 项（批次 1-2 已确认 CE 筛选为固定属性筛选）；工作项详情、intake 均无 AI 操作。
- CE 侧需记录的基线形态即「以上云端入口在 CE 全部不存在」（截图 ce-no-ai-baseline-20261114.png）。

## 深测补充（2026-11-14 下午）

> 环境：同一工作区（YM Research/thinkym）。下午首次进入 AI 工作台时出现 Build 能力激活卡，本批实测先激活再对话，共产生 4 个 thread、1 个 Build 创建的 Wiki 页。会话/技能/Build/summary 均真实读到了工作区数据。下午后段周配额耗尽，部分流程被硬中断（中断形态本身已记录）。

### 1. AI 会话对话实测（能否读数据/回复形态/会话保存/模型）

- **能读工作区数据，且是 agentic 检索而非纯聊天**。问「列出 thinkym 项目中所有未完成的工作项」→ 回答「共有 6 个未完成的工作项」并给出 markdown 表格（唯一标识/标题/状态/优先级，THINK-2..7 全部正确，ID 渲染为可点击链接）。
- 回答过程展示可折叠的执行轨迹（中文界面、英文步骤文案）：Thoughts → "Homed in on the key areas"（展开可见 **Retrieval Tools** 推理：点名 `workitems_workspace_filter` 这个 PQL 检索工具）→ "Picking the right wrench..." → **PQL** 折叠块（Query 自然语言 + PQL 语句；PQL 中项目以内部 UUID 掩码显示 `project = "xxxx-3dac"`）→ "Turning the findings over..." 等步骤。
- **回复内嵌可操作 PQL artifact 卡**：`project = thinkym AND stateGroup NOT IN ("completed", "cancelled")`，带 Copy / **Create View**（一键把该查询存为项目视图）/ Expand editor；结尾还会提示「如需保存这个筛选条件，可点击上方 + Create View 创建视图」——AI 对话与 PQL 筛选（D-04/D-05）形成闭环。
- 消息级操作栏：复制、好的回复/不好的回复、**重写**、**转换为页面**（把 AI 回答转成 Wiki 页）。
- 会话保存形态：每个 thread 独立 URL `/thinkym/ai-chat/<uuid>/`，标题自动取问题的英文摘要（如 "List incomplete work items in thinkym project with statuses"），列于侧边栏「最近」；无手动重命名入口。
- 流式速度慢：答案表格逐行流出（约 30–60 秒/行），6 行答案完整呈现约需 5 分钟；期间行内单元格先出 ID 后补标题/状态。
- 模型：输入区模型选择器默认 **Claude Sonnet 5.5**（带下拉箭头）；周配额耗尽后该按钮从 DOM 消失（仅剩 Build/web search/录音）。分析页证实后端实际调用 Claude Sonnet 5.5（99.6%）与 Claude Haiku 4.5（0.4%，推测用于轻量任务如标题生成）。

### 2. 技能（Skills）实测

- 技能页（/ai-skills，测试版 badge）12 个系统技能全集含描述：/my-work、/standup、/project-status、/cycle-report、/team-workload、/blocked-items、/needs-attention、/recent-activity、/find-pages、/time-tracking、/file-bug(Build mode)、/new-prd(Build mode)；另有 工作区级别/个人 两个 tab 与「添加工作区技能」。**卡片为纯展示（无运行按钮）**。
- 技能执行入口在聊天输入框敲 **"/"**：弹出斜杠菜单列出全部 12 技能 + 「管理技能」跳转；选中后以 `/standup` chip 形式插入输入框，发送即执行。
- **/standup 实测输出**：会话内结构化报告，分 **Completed / In progress / Blocked** 三段，每段各带一张 PQL 卡（`assignee = currentUser() AND stateGroup = "completed" AND updatedAt >= "2026-11-13"` 等，Copy/Create View 可用）+ 一句结论；AI 自行做了日期推理（"Today is Saturday, so the last working day is Friday, Nov 13"）与用户身份解析（Users 工具）。**产出只留在会话内，不写评论/不建页面**。

### 3. Build 模式实测

- 首次进入 /ai-chat/ 时整屏显示激活卡：「Plane AI 现在可以为您执行操作。使用 Build 模式创建工作项、周期等。立即激活以启动 Plane AI 操作」+「激活 Plane AI」按钮；激活前无聊天输入框。激活为一次性工作区级动作。
- 输入区 Build 按钮实为**三档模式下拉：Ask（只答）/ Build（执行需确认）/ Autopilot（自动执行，本次未实测）**。
- 实测请求：「在 Wiki 中创建一个页面，标题为『本周工作项清单』，内容为 thinkym 项目当前所有未完成工作项的清单」（Build 档）。
- **确认流程=先预览后执行**：AI 先用 PQL 取数，然后在会话里给出计划说明（「我已规划好在 Wiki 中创建页面…你确认后才会真正创建」）+ 页面内容预览 + 动作卡「本周工作项清单 | Edit | Awaiting response – Please confirm the actions you want to execute | **Confirm**」。点击 Confirm 后卡片变「**Action successfully completed / 1 successful action**」并附页面链接；展开该卡只有动作明细，**无撤销/回滚入口**。
- 实际产出：Wiki 的 General 集合下新建页面「本周工作项清单」，内容为 6 条工作项清单（ID—标题—状态，优先级:高/低/无）。URL：`https://app.plane.so/thinkym/wiki/78e4df4c-7e4c-49a2-90a8-851c7cce27ef/`（保留不删）。
- 附带发现：Wiki 页面编辑器工具栏自带**页面级「AI summary」按钮（Powered by Plane AI）**，页面下方还有情境 AI 面板（建议「Create relevant work items with actionables from this page」等）。

### 4. AI summary 实测（工作项）

- 前置：给 THINK-1 添加了一条测试评论（评论编辑器：格式工具栏 + 「评论」提交按钮）。
- 入口：工作项详情页顶栏「AI assistant」面板的建议项 **"Add a comment summarizing all the activity/comments pertaining to the work items blocking this one"**（与上午记录一致的三条建议之一；点其它建议同样自动填 prompt）。点击后 prompt 自动插入面板输入框（自动挂 Thinkym 项目 chip + THINK-1 chip）并**自动发送**。
- 执行轨迹显示其规划：Work items（list_dependencies/list_relations 找阻塞项）→ Activity → Comments → **在目标工作项上创建一条 summary 评论**（即意向输出形态=评论，非页面/弹窗）。
- 本次运行被配额硬中断（见 §7），summary 评论未真正落盘；生成完成后的形态留待额度恢复（11-16）后补测。

### 5. 记忆（Memory）页

- 文案「Plane AI 会从您的对话中学习…」；「查看和管理记忆 · 尚未写入」区块；主体为空态卡「**记忆已停用**——此工作区当前已停用记忆。请联系工作区管理员启用」+「前往工作区设置」按钮。即记忆默认关闭、需工作区级开启，开启后此处管理可增删的记忆条目。

### 6. 分析（Analytics）页

- 「查看工作区 AI 消耗的详细用量细分洞察」；**个人 / 工作区** 两个 tab；「用量细分」三维度切换：**模型 / 功能 / 范围**；月份切换（Nov 2026）+ **导出** 按钮。
- 实测读数：模型= Claude Sonnet 5.5 99.6% + Claude Haiku 4.5 0.4%；功能= Build 100%（本次会话均计入 Build）；范围= Workspace 100%。

### 7. 用量与配额（Business trial）

- 用量页双层百分比配额：**月度用量**（40.5% 已使用，第 14/30 天，Dec 01, 2026 重置）+ **本周**（116% 已使用，「已达上限」红条，Nov 16, 2026 重置）；「用量趋势」图（周/月切换，按日百分比曲线）。口径说明：「您直接调用 AI 时消耗的用量，包括 Plane AI 聊天、标签预测、重复项检测以及与智能体对话」。
- **无 credits 余额概念**，纯百分比配额；也未见按模型分价。
- 达限行为（实测）：① 所有 AI 输入区（ai-chat、首页 Ask 卡、上下文侧栏面板）上方挂横幅「您已达到 Plane AI 使用上限。Nov 16, 2026 重置 · 查看用量」；② **运行中的 AI 任务被硬中断**（会话内提示 "Your AI usage limit ran out. It resets on Nov 16, 2026 at 00:00 UTC."）；③ 模型选择器从输入区移除；④ 面板侧栏常驻「您已使用上限的 90%→已达上限」status。侧栏底部另有「Business trial ends in 13d」试用倒计时。
- 与代码盘点的对应：enterprise helm 的 plane-pi（自托管 BYO LLM）在 UI 无任何模型配置入口——用量/分析两页即云端侧 Plane Intelligence 的消费呈现，对应 SDK 暴露的 agent_runs/artifacts 端点；CE 自托管若接 plane-pi 预期复用同一套 ai-chat UI 但配额层不同（待后续自托管实测验证）。
