## 3. 结论摘要（三类统计）

**核心发现：CE v1.5.0 与云端 Business 前端共用同一套设计 token 体系（@makeplane/propel），双主题颜色值经浏览器 computed 实测几乎逐项一致**——追赶的主战场不在 token 层，而在组件形态层（卡片密度/边框风格）与全新页面层（见 02/03 文档）。

| 文档             | 规模                                                                | 三类结论统计                                                                                         |
| ---------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 01.设计token对照 | 5 类共 **76 项**（颜色 26 / 字体 13 / 间距 17 / 圆角 13 / 阴影 10） | 一致 64 ｜ 差异 9 ｜ CE 有名云端未暴露 8                                                             |
| 02.组件覆盖矩阵  | **54 行**                                                           | 直接可用 31 ｜ 需改造 7 ｜ 需新增 16                                                                 |
| 03.页面状态矩阵  | **30 行**（覆盖 20-65 全部模块代表页）                              | 已覆盖状态多数有历史截图背书；本批补采：窄屏×2、错误态×3、加载态×1、看板空列×1                       |
| 04.键盘与交互流  | 快捷键逐项对照 **77 行** + 交互流 5 节                              | 快捷键：云端多 13 条（团队空间/计划/仪表板/客户/AI 助手）；工作项操作键 CE 全部带 ⇧ 前缀、云端为裸键 |

三类结论口径：

- **直接可用**：CE 已有同名/同构实现（propel 组件或 blocks 组件），数值或形态与云端一致，不需要动。
- **需改造**：CE 有实现但形态与云端有可见差异（如看板卡片圆角/描边、列底色、面板宽度）。
- **需新增**：云端用到、CE 无任何实现（如 widget 网格卡、自动化画布、AI 面板、Stickies 等）。

## 4. 核心发现（Top 5）

1. **Token 同源**：云端浅色/深色全部采集变量（26 项）与 CE `@makeplane/propel@0.9.7` 的 `variables.css` 数值一致（oklch 体系、`--bg-*/--txt-*/--border-*/--priority-*` 命名同构）。仅发现 3 处漂移：浅色 `--bg-backdrop`（云端 30% 黑 vs CE 50% 黑）、`--shadow-raised-100/200`+`--shadow-overlay-100`（云端 root 已 unset，仅保留 raised-300/overlay-200）、`--padding-page`（CE 定义 1.35rem，云端 unset）。追赶时可把 CE 的 propel 升到云端同版本即可对齐。
2. **组件层差距集中且可枚举**：云端 54 个组件样本中 16 个在 CE 完全缺失，全部聚集在商业功能页（widget 网格、自动化画布节点、AI 面板、Stickies、Initiative/客户/Wiki 树、高级搜索页、CSV importer 向导、计费 plan 卡）。基础组件（按钮/菜单/弹窗/表格/tab/开关/徽章）100% 对齐。
3. **看板卡形态差异**（最直观的视觉差）：云端卡片 = 无边框、12px 圆角、浮在 8px 圆角的灰底列（bg-layer-1，列宽 336px）；CE 卡片 = 1px 描边、8px 圆角、白底、列透明（列宽 310px）。这是一处低成本高感知的改造点。
4. **键盘体系两代**：云端工作项操作已迁到裸键（S/P/A/E/C/M/L），CE 全部为 ⇧ 前缀（⇧E/⇧C/⇧M/⇧S）；复制类云端裸键（. ' ,），CE 为 ⌘ 系（⌘. / ⌘⇧' / ⌘⇧,）。序列键（N-then/O-then/G-then）两侧同构，云端多出 团队空间/计划/仪表板/客户记录 4 组。云端新增「打开 AI 助手 A」。
5. **窄屏两侧都未做响应式**：375px 宽度下，两侧侧边栏均占满整屏、主内容被裁切（无横向滚动、无汉堡折叠）。移动端适配是两版共同空白，追赶时可按自身优先级设计。

另记录一个云端小缺陷（追赶时避免复刻）：云端侧边栏「更多」展开按钮 aria-label 未翻译，直接显示 i18n key `aria_labels.app_sidebar.open_extended_sidebar`（dom 观察，2026-11-14）。

## 6. 未覆盖点

- **无权限态页面**（受限角色视图）：试用账号为工作区 Admin，无法在不建第二账号的前提下触发受限视图；仅引用 55 模块的公开 API 401 证据。原因：造数成本与「不建不需要的测试数据」约束冲突。
- **超长文本态**：未专项构造超长标题/描述页（现有测试数据无超长样本）；仅可引用 20 模块列表布局 DOM 快照中的截断 class（`truncate`）作为 CE 行为证据，云端未复核。原因：低风险常规实现，优先级让位给窄屏/错误态。
- **拖拽过程态**（拖拽幽灵/落点指示线）：静态采集无法稳定触发 drag 事件的中间态帧，引用 59 模块 `cloud-dashboard-layout-drag/after-drag` 前后对照与 20 模块 DOM 快照的 `draggable=true` 证据，不做过程态断言。
- **仪表板 widget 卡 computed 数值**：dashboards 列表页未进入具体 dashboard 详情（widget 网格），widget 卡样式结论为 visual 级。原因：59 模块已有完整 DOM 快照与截图，避免重复登录采数。
- 表格布局（spreadsheet）单元格编辑态、甘特拖拽把手等深层交互态：20 模块已覆盖结构，本批不重复。
