## 全局结论

1. **API 面**：EE 走独立 `api_v2` app（REST，路径 `/api/v2/workspaces/{slug}/...`），407 operations；CE 只有 `api/v1`（`apps/api/plane/api/urls/__init__.py`，12 类资源）。追赶建议**新建 v2 前缀**而非塞进 v1，保留 v1 兼容。
2. **命名规约**：EE 资源路径 kebab-case（`work-item-types/`、`audit-logs/`、`worklogs/`），写操作统一 `POST create / GET retrieve / PATCH partial_update / DELETE destroy`（无 PUT），子资源管理统一 `{add: [], remove: []}` bridge 语义，响应 `added/removed`。
3. **模型规约**：EE 模型普遍带 `external_id/external_source`（同步友好）、软删（`deleted_at`，SDK 读模型回传 `deleted_at`）、`created_by_id/updated_by_id` 命名（v2）vs CE 的 `created_by/updated_by`（v1）。
4. **Feature flag**：workspace 11 + project 7 = 18 个布尔 toggle（SDK `models/v2/features.py`），全部通过 `GET/PATCH .../features/` 暴露；CE 的 `Project` 已有部分字段可对齐（`is_time_tracking_enabled` 等）。
5. **schema 冲突预案通用原则**：追赶新建表一律用 CE 的 `BaseModel/ProjectBaseModel/WorkspaceBaseModel` 基类（`apps/api/plane/db/models/base.py`、`project.py:230`、`workspace.py:185`），保证 `id(UUID)/created_at/updated_at/deleted_at/created_by/updated_by` 与官方同构；官方升级时差异收敛到「官方新增字段缺列」（可 `makemigrations --empty` 补列）与「官方改列类型」（罕见）两类，避免自造表名/字段名。
