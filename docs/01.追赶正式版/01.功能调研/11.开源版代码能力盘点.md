## 3. 分类详述

### 3.1 Feature flag / 许可机制

**结论：开源版没有 license 校验和云端 feature-flag 下发机制；所有"付费墙"在代码层不存在，仅有一处显式的 edition 硬门（外部 API 的 PQL 过滤器）。**

- 版本枚举被裁剪：`InstanceEdition` 只定义 `PLANE_COMMUNITY`，实例 `edition` 字段默认即此值 — `apps/api/plane/license/models/instance.py:18-29`。注册命令也强制写回社区版：`apps/api/plane/license/management/commands/register_instance.py:74,86`。
- 唯一的 edition 硬门：外部 API v1 列 work items 时若带 `pql`/`filters` 参数直接返回 400 "not supported on this Plane edition" — `apps/api/plane/api/views/issue.py:393-403`。
- 无 `ee/` 目录、无 `plane/billing`、无 PaidFeature gating 中间件。全仓 grep `is_premium|isOnFreePlan|PRODUCT_EDITION|/ee/` 均无业务命中。
- 遥测即"计量上报"：`apps/api/plane/license/bgtasks/telemetry_metrics.py` 用 OpenTelemetry 把 user/workspace/project/issue/module/cycle/page 计数推给 OTEL collector；`Instance.is_telemetry_enabled` 默认 True，god-mode General 页可关（`apps/admin/app/(all)/(dashboard)/general/form.tsx:131`）。
- 版本检查：注册实例时请求 GitHub API `makeplane/plane/releases/latest`（`register_instance.py:41-53`），结果仅存库展示。
- 前端遗留升级 UI：`apps/web/components/workspace/edition-badge.tsx`（侧边栏 "Community" 徽章）→ `apps/web/components/license/modal/upgrade-modal.tsx`，套餐文案硬编码于 `packages/constants/src/subscription.ts`（Enterprise/Business/Pro/One 的 feature 列表，即云端在售套餐的能力清单——是本次追赶调研的重要输入）。该弹窗纯展示，无支付调用。

### 3.2 项目管理核心模型

**结论：核心模型齐全且为开源主力；时间跟踪、teamspaces、自动分派没有。**

- 模型全目录：`apps/api/plane/db/models/` — `issue.py`（含 `IssueVersion:677`、`IssueDescriptionVersion:782`）、`module.py`、`cycle.py`、`view.py`（项目视图 + workspace global view）、`page.py`（含 `PageVersion:158`、`access` 公开/私有 `page.py:37`）、`intake.py`（`Intake:16`/`IntakeIssue:54`）、`draft.py`（DraftIssue 及关联 5 表）、`sticky.py:16`、`estimate.py`、`issue_type.py`、`label.py`、`state.py`、`favorite.py`、`recent_visit.py`、`notification.py`、`exporter.py`、`importer.py`、`webhook.py`、`deploy_board.py`、`api.py`、`session.py`、`device.py`、`social_connection.py`、`integration/`。
- 前端 MobX store 对应：`apps/web/store/`（issue/module/cycle/pages/inbox/sticky/estimates/notifications 等）。
- 开关型子功能在项目 Features 设置：`apps/web/app/(all)/[workspaceSlug]/(settings)/settings/projects/[projectId]/features/{pages,views,modules,cycles,intake}/page.tsx`，后端字段在 `Project`（如 `is_time_tracking_enabled` — `apps/api/plane/db/models/project.py:100`）。
- 明确缺失：auto-assign（无任何代码）、time tracking 记录实体、teamspaces、依赖关系外的进阶字段（如甘特基线）等。

### 3.3 实时协同（apps/live）

**结论：Hocuspocus 只服务 Page 正文协同；work items 不是实时的。**

- 文档范围：`apps/live/src/extensions/database.ts:26-138` — `fetchDocument`/`storeDocument` 仅以 pageId 拉/存 `description_html` 二进制（走 API `fetchDescriptionBinary/updateDescriptionBinary`）。标题同步扩展 `src/extensions/title-sync.ts`、`title-update-manager`。
- 多实例横向扩展：Redis 扩展 `src/extensions/redis.ts` + `src/redis.ts`；部署错误广播 `src/utils/broadcast-error.ts`；优雅排水 `src/lib/drain-server.ts`。
- 附加能力：Page PDF 导出 schema `src/schema/pdf-export.ts`（A4/A3/…、横竖版）；管理命令用 `LIVE_SERVER_SECRET_KEY` 头鉴权（`src/lib/auth-middleware.ts:36`）。
- 前端接入：编辑器协作 provider（`apps/web/components/pages/editor/editor-body.tsx` 为 web 内唯一 WebSocket 使用点）；`packages/services/src/live.service.ts` 只是 base class。
- Work items：无 WS 订阅，列表/详情为 REST + MobX（SWR/手动 refetch），云端"real-time collab"页面级之外的对象不适用。

### 3.7 企业能力（SSO/权限/审计/会话）

**结论：OAuth(OIDC-like) 四家 + 邮箱 + magic link 可用；SAML/SCIM/LDAP/OIDC-discovery 完全没有；无自定义角色。**

## 5. 疑问 / 不确定点

1. **`plane/space/views/{cycle,module,state,label,meta}.py` 未注册路由**：文件齐全但没有挂到 `space/urls/__init__.py`。不确定是"开源版刻意裁剪"还是"重构遗漏"。若目标是补齐 Space 公开页能力（公开 cycle/module），挂路由即可复用，但需确认序列化器是否泄露私有字段。
2. **Dashboard widgets 的边界**：`dashboard.store.ts` 仍在 root store 挂载且 service 指向不存在的端点；无法确定云端的"home dashboard"是否即由 `/dashboard/` + widgets 提供。追赶"仪表盘"功能时需以云端实际抓包为准。
3. **AI 前端入口的可见性条件**：`ai.service.ts` 存在，但未逐点确认编辑器工具栏 AI 按钮是否根据实例配置（有无 LLM key）动态显隐；从后端逻辑看未配置时返回 400，前端应有降级，待 UI 实测。
4. **`GITEA` OAuth 在 god-mode 的暴露程度**：配置变量齐全（`IS_GITEA_ENABLED` 等），admin 后台 Authentication 页面的表单字段是否含 Gitea 未逐一核对；env 方式一定可用。
5. **Device/DeviceSession 模型的实际用途**：`plane/db/models/device.py` 定义了设备与会话绑定表，但未找到对应的 API 视图；疑似为云端"会话管理/强制下线"预留的本地底座，状态=仅有模型。
6. **Webhook 事件全集**：`packages/types/src/webhook.ts` 的布尔位与后端 `webhook_task.py` 分发的事件需逐一对齐（本地看到 issue/issue_comment/cycle/module/project/intake 相关 serializer 引用），完整事件矩阵建议以 `webhook_task.py` 的分支为准做一次精读。
7. **`workflow.json`/`automation.json` locale 的消费方**：未找到对应前端页面消费这些键（部分键可能被通用组件引用）；说明云端 Workflow/Approvals、Automation Flow 是纯增量功能，开源追赶时无现成 UI 骨架可复用（仅有文案）。
