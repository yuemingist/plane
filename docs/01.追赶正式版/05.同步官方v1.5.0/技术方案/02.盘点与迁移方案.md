## 2. A/B/C 分类

### A. 后端 / API（apps/api 42 文件 + 4 迁移）——建议：合并 + 逐文件语义审查

- 4 迁移（0126-0129）+ lockfile：直接沿用。
- 新模型/ViewSet/URL：workflow（0126）、issue_property（0127 三表）、workflow transition（0128）、type available states（0129）——**新增文件为主**，官方未动同名文件，可平移。
- 双方同文件的高危点（官方安全修复大改 view/serializer 层）：`app/serializers/issue.py`（我们的 type_id/property 校验 vs 官方 guest 限制与系统字段只读）、`app/views/issue/base.py`（values 补列 vs 官方动词越权修复）、`bgtasks/issue_activities_task.py`、`utils/filters/filterset.py`、`utils/grouper.py`。试跑显示这些文件自动合并成功——**逐个 diff 审查语义**（尤其官方「guest 限制扩展」「系统字段只读」「动词白名单」是否被我们的追加破坏）。
- pytest 105 条自有用例预期可平移；`assertNumQueries` 类断言若官方改动查询数需修正。

### B. 机械前端（i18n 89 + constants + types + utils 少量）——建议：合并 + 机械适配

- i18n 键（22 locale × 若干新键）：官方 v1.5.0 的 locale 结构若重构，按新结构挂接（官方新增保加利亚语等——locale 文件可能整目录变化，注意合并策略）。

### C. 设计系统相关 UI（apps/web 组件 77 文件中的新增组件群）——建议：按 Propel 新组件重做/适配

- 新增组件（不冲突但依赖旧体系）：work-item-types/\*（类型/属性/层级/状态配置）、workflow 设置页、issue-property 侧栏分区、type-select/type-chip、epic 页、project-states 修改。

- 适配方式：编译驱动——merge 后 `pnpm check:types` 的报错清单即重做任务清单；再浏览器逐页核对（专家审核重点）。

## 3. 迁移方案

1. `sync/v1.5.0` 从 main 拉出 → `merge v1.5.0`（预期零冲突，直接进）。
2. `pnpm install`（依赖大版本变化）→ `pnpm check:types` 收集报错清单 = C 类任务清单。
3. 逐文件适配（A 审查 → B 机械 → C 重做），每批提交。
4. pytest 全量（容器）；浏览器逐页冒烟（截图供事后专家复核）。
5. 质量闸门：自测全绿 + 事后专家复核（D66 修订=明晚 glm 出第一版与截图，gpt-6-astra 明日复核，必须修复项关闭后本步才算最终验收——**今晚先合 main 部署，复核意见如有必须修复项以后续 fix 分支处理**）。
6. 迁移编号冲突预案：无撞号，无需 renumber；若官方 preview 后续新迁移越过 0129 再处理。
