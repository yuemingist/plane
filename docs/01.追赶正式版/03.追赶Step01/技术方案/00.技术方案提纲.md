# 00. 技术方案提纲（Step01）

> 状态：提纲｜2026-11-15｜请技术专家按本节把正式技术方案写在本目录（建议文件名 `01.技术方案.md`）。以 [P0-4 brief](../../01.功能调研/16.改造切入点/P0-4-Epics与Types后端路由及设置页.md) 为起点，偏差必须写明理由。依据见 [00.子项目章程](../项目管理/00.子项目章程.md)。

正式方案建议覆盖以下各节。模型层已有 `IssueType` / `ProjectIssueType` / `Issue.type` / `is_issue_type_enabled`，按 brief 默认 **0 个新迁移**（除非论证必须加字段）。

## 1. 现状与可复用

复核 P0-4 §2：模型、缺失的 API 路由、前端 epic store/组件/i18n 存量、设置页 404。用路径与行号举证。

## 2. 后端

- IssueType ViewSet：CRUD、设默认、项目启用（自动建 Epic + Task）、权限与开关门控。
- ProjectIssueType 绑定。
- Epics ViewSet：独立新文件，按 `type.is_epic` 过滤，不直接改 IssueViewSet（上游冲突规避）。
- URL 与序列化；Guest 只读。
- 本步不做自定义属性表。

## 3. 前端

- 设置页目录、路由、侧栏「工作结构」注册。
- 启用门卡、类型 tab、属性 tab 空态、层级 tab 只读。
- service / store / 类型定义 / i18n（只追加键，不重排官方 locale）。
- 段 1b 贯穿改动面：详情、新建弹窗、显示列、筛选。
- Epic 布局入口如何点亮。

## 4. 测试策略

API 用例、E2E 关键路径、与现有造数（WEB 项目已直插类型）的兼容。指向测试计划。

## 5. 上游冲突与风险

P0-4 §8、§9 的条目要逐条回应（含层级是否可编辑仍未确认、启用自动建类型与官方 seed 可能不完全一致、属性空态避免误导）。

## 6. 任务拆分与并行

建议的后端 / 前端 / 贯穿子项拆分，以及与段 0 状态核对的关系。估算若与 12–15 + 5–8 人天有出入，给出修正值与理由。
