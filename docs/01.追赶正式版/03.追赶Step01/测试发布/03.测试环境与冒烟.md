## 2. 环境红线（08 号工作约定 §6 摘录，执行期间全程有效）

1. **禁止 `docker compose down -v`**（会删掉测试库；日常停启用 `down` / `up -d`，数据卷保留）。
2. 不删除账号内数据、不改系统安全设置与凭据；云端 app.plane.so 只读浏览，不点删除/修改/付费按钮。
3. 服务挂了按 [首次部署 README](../../../运维/首次部署/README.md) 的「日常启停」一节拉起，**不要**无故重部署一整套。
4. **本步无生产发布**：全部验收只在测试环境进行；合并 `main` 与任何对外部署必须明哥点头（08 号 §7）。
5. 文档与测试阶段不自行 commit/push/切分支（08 号 §1）；执行者只写文件，由统筹提交。

## 4. 拉起流程（环境挂了时）

严格按 [docs/运维/首次部署/README.md](../../../运维/首次部署/README.md)「日常启停」执行，要点：

1. Docker 后端：`cd ~/Develop/plane && docker compose -f docker-compose-local.yml up -d`（**不带 -v**）。
2. 前端：按 README 逐行粘贴 5 条 `tmux new-session/-window` 命令（`-c vite.config.local.ts` 本地配置包装，不要直接跑根目录 `pnpm dev`）。
3. 等 ~40s 就绪 → 跑一遍 §3 清单（H1~H12）确认全绿 → 记录拉起时间与原因到本文件 §6 运维记录。
4. compose 重启后必须看 H2（migrator 日志）确认迁移完成。
