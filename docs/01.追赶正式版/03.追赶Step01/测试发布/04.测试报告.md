### 2.1 D6 先复验结论（先行项）

**复现。** 编辑 Todo 打开行内表单：名称输入框显示为空（placeholder「State name」正常显示），描述同样为空。

- 源码核对（只读）：`8cc0657b64` 已含防御式快照修复 `apps/web/components/project-states/create-update/form.tsx`（`if (data && !formData) setFromData({ ...data })`），说明**修复代码已实现但实测未在显示层生效**。
- 佐证观察：表单打开瞬间「更新」按钮为可点态（disabled=false）；手动清空输入后「更新」变为置灰、输入后恢复可点——说明 React state 中 name 实际已被预填（禁用逻辑 `!formData?.name?.trim()` 判定非空），**但 controlled input 的 DOM 显示值仍为空**。即：数据层预填成功、视图层未渲染，用户看到的仍是空名称框（与云端行为不一致）。
- 定级：缺陷 **BUG-01**（中；功能可用——此时点「更新」会以原名提交，但与 Business「编辑时名称预填」的行为直接不一致，且用户直接改描述提交会把名称覆盖为原名，属可见交互缺陷）。

### BUG-01 编辑状态表单名称未在输入框显示预填（D6 复现，中）

- **现象**：编辑既有状态（如 Todo）时，行内表单名称输入框显示为空（placeholder「State name」正常）；但「更新」按钮呈可点态，手动清空输入后「更新」变置灰——证明 React state 中 name 已被预填，仅 controlled input 的 DOM 显示值未渲染。
- **步骤**：项目设置→状态→Todo 行菜单→编辑→观察名称输入框。
- **证据**：ce-e2e-TC-S0-R6-edit-form-2026-11-16.png；对照 ce-e2e-TC-S0-R7-edit-cleared-2026-11-16.png（清空后 disabled=true）。
- **定位提示**：`apps/web/components/project-states/create-update/form.tsx` 的防御式快照修复（`setFromData({ ...data })`，commit `8cc0657b64`）已让 state 层拿到数据，怀疑 InputField（@makeplane/propel）controlled value 在挂载后更新时未同步 DOM 显示，需排查 InputField 的 value 透传/内部状态。
- **影响**：与 Business「编辑名称预填」行为不一致；用户直接改描述提交会把名称以原名覆盖提交（无破坏但行为怪异）。段 0 关闭被此缺陷阻塞（见 §2.4）。
- **修复（2026-11-16）**：`form.tsx` 初始化改为 `useState(() => (data ? { ...toJS(data) } : undefined))` 同步构建 plain 快照（mobx observable 深拷贝），受控输入自首帧起即有值，消除「undefined→value 挂载后更新」时 InputField DOM 显示不同步的根因；已修复待复验（复验 TC-S0-R6 + TC-S0-001，commit 待提交）。
- **复验结论（2026-11-16 复验轮，commit `b664cf9376`）**：✅ 通过——编辑 Todo 名称输入框首帧即显示「Todo」（见 §8.4）；段 0 据此关闭。
