# 00. 子项目章程：追赶 Step01 — 工作项类型与状态

> 状态：已确认｜2026-11-15｜明哥拍板后由 Plane助理落盘。细节决策见 [docs/项目管理/02.会议与决策记录.md](../../../项目管理/02.会议与决策记录.md) D41–D44。

## 1. 为什么做这一步

明哥不以原 M1 切片的 8 问来规划路线，改用 Autovado 的实际用法校准方向：先补「工作结构」里最关键的能力。Autovado 只是方向，**本步不要求完成 Jira 迁移，也不与同事正在用的 Jira 同步**。

第一个目标收敛为：把开源版的**工作项类型**（并核对**状态**）追平 Business 正式版。工作流留到类型完成后再排。

## 2. 目标

将开源版项目设置「工作结构」中的工作项类型，改造成与 Plane.so Business 正式版相同的功能、UI 与操作；并核对状态页与正式版的差异——有则补齐，无则书面确认已对齐。

对标档位是 **Business**（云端 thinkym 试用环境实测口径），不是 Enterprise。

## 5. 验收标准

段 0：提交状态核对结论（已对齐 / 待补差异清单）。若有待补项，补完后与 Business 状态页对照通过。

段 1a（摘自 P0-4 验收，可在产品方案中细化）：

1. 未启用项目打开工作项类型设置页，显示门卡和「启用」，不再 404。
2. 启用并确认后，出现 Epic（活动）+ Task（默认·活动），`is_issue_type_enabled=true`。
3. 新建类型默认「已禁用」，行菜单含设为默认（未激活时禁用）/ 编辑 / 启用 / 删除。
4. 默认类型不可删除，提示文案对齐正式版。
5. 可创建 Epic 工作项，并在 Epic 布局可见。
6. 在 Epic 下添加子工作项时，类型下拉排除 Epic。
7. 层级 tab 只读展示「层级 1：Epic → 层级 0：Task/自定义」。
8. 未启用项目调用类型 API 被开关门控（403/400）。
9. 属性 tab 为空态，不出现可创建属性的完整能力。

段 1b：详情可切换类型（含确认文案与活动留痕）；新建可选类型；列表可打开类型列；筛选含 Type / Parent type。

总原则：功能、UI、操作与 Business 正式版一致；文案与交互以 57 号流程表和云端截图为准，不另发明一套。
